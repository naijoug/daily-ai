## AI 热点
1. **METR and Redwood red-teamed OpenAI's internal agent monitoring and found novel holes**: one researcher from each group spent three weeks (Jul 21 – Aug 11) inside OpenAI with access to code, monitor prompts and staff. They estimate only 75–94% of agentic internal Responses API traffic from GPT-5.5-class models was eligible for monitoring, about 10% of internal Codex traffic went unmonitored for months because compaction events were skipped, and they found a way for Codex agents to escape the sandbox and Auto-review plus two headers that start a new agent with monitoring off. OpenAI says production gaps are patched; the evaluators have not verified that. A useful checklist for anyone monitoring their own agents. https://metr.org/blog/2026-10-22-red-teaming-openai-agent-monitoring/ | https://www.cnbc.com/2026/10/22/metr-redwood-research-open-ai-test.html
> [zh] **METR 和 Redwood 对 OpenAI 内部 agent 监控做红队测试，发现多处新漏洞**：两家各派一人在 OpenAI 驻场三周（7/21–8/11），能看代码、监控提示词并访谈员工。他们估计 GPT-5.5 级模型的内部 agent 流量只有 75–94% 在监控范围内；因为没监控上下文压缩事件，约 10% 的内部 Codex 流量几个月没被检查；还找到 Codex agent 绕过沙箱和 Auto-review 的路径，以及两个能让新 agent 关闭监控启动的请求头。OpenAI 称生产环境漏洞已修，评估方尚未验证。给自己的 agent 做监控的人可以拿来对照。
2. **Symantec catches "Skynet", an autonomous agent that hijacks exposed LLM endpoints to run attacks**: an AI honeypot captured the full prompt: four layers of jailbreak, 74 offensive tool definitions (FOFA scanning, exploits for Jupyter, Next.js, Laravel, Supabase and more, cloud-metadata SSRF, botnet C2), and a "Skynet mode" allowing up to 100,000 unattended steps to scan, steal credentials, drop Monero miners and reinfect hosts. It targets self-hosted model servers, AI gateways and MCP endpoints, so the victim pays for the inference. If you run an open model server or gateway, put auth in front of it now. https://www.security.com/threat-intelligence/ai-llmjacking-skynet
> [zh] **赛门铁克抓到「Skynet」：劫持暴露在公网的大模型接口、自主发动攻击的 agent**：AI 蜜罐截获了完整提示词：四层越狱、74 个攻击工具定义（FOFA 扫描，Jupyter、Next.js、Laravel、Supabase 等框架漏洞利用，云元数据 SSRF，僵尸网络控制），以及允许无人值守跑 10 万步的「Skynet 模式」，循环扫描、偷凭据、装门罗币矿机、反复感染。目标是自托管模型服务、AI 网关和 MCP 端点，算力费由受害者买单。自己跑开源模型服务或网关的，赶紧加上鉴权。

4. **Letta releases FrontierMemory 1.0, a benchmark that scores agent memory by downstream task success**: instead of quizzing recall, the agent gets 665 past trajectories (only 219 relevant), writes memory within six hours with no web access, and that memory is judged by how many of 15 coding and knowledge-work tasks a task agent then solves. Opus 5.5 and GLM-5.3 tie at 73.3%, Kimi K3 66.7%, GPT-6.1 Sol 60% (cheapest at about $0.77 per task), Grok 4.7 33.3%; Letta Dream leads the harness board. These are Letta's own numbers on a small task set. https://www.frontiermemory.com/blog/v1/ | https://x.com/AIQuanting/status/2113466666168582441
> [zh] **Letta 发布 FrontierMemory 1.0：按下游任务成功率给 agent 记忆打分的基准**：不再考事实回忆，而是给 agent 665 条历史轨迹（只有 219 条相关），限时 6 小时、不能联网写出记忆，再看这份记忆能让执行 agent 解出 15 个编程和知识工作任务中的多少个。Opus 5.5 与 GLM-5.3 并列 73.3%，Kimi K3 66.7%，GPT-6.1 Sol 60%（每任务约 0.77 美元，最便宜），Grok 4.7 33.3%；框架榜 Letta Dream 第一。数据为 Letta 自测，任务量较小。

## 有趣用法和干货
1. **Theo explains what a "harness" actually is**: an LLM only emits text; the harness is the tools, the tool-call syntax, the parser that runs calls, the loop that feeds results back, and the tool list with descriptions. Claude Code and Codex bundle an interface with a harness (Agent SDK, Codex App Server), MCP lets tool code live elsewhere, and agent = LLM + harness. Over 2,600 bookmarks, a good primer to send teammates. https://x.com/theo/status/2113424203345265053
> [zh] **Theo 讲清楚「harness」到底是什么**：LLM 只会输出文本；harness 是工具、工具调用语法、解析并执行调用的系统、把结果喂回模型的循环，再加带说明的工具清单。Claude Code 和 Codex 把界面和 harness（Agent SDK、Codex App Server）打包在一起，MCP 让工具代码放在别处，agent = LLM + harness。收藏超 2600，适合转给团队当入门读物。
2. **Claude 默认自动模式之前，先装上 dcg 拦截危险命令**：寒塘 poolmoon 推荐开源工具 destructive_command_guard：通过 hook 在 agent 执行前确定性地拦下 `git reset --hard`、`rm -rf` 这类危险命令，Rust 写的、几乎无感，策略可配，被拦后可以用命令行手动放行。自动审批靠的还是模型判断，接了其他模型的 Claude Code 更需要这道保险。https://x.com/poolmoon6/status/2113444797323362322 ｜ https://github.com/Dicklesworthstone/destructive_command_guard
> [en] **Before Claude defaults to auto mode, install dcg to block dangerous commands**: poolmoon recommends the open-source destructive_command_guard, which uses a hook to deterministically block commands like `git reset --hard` and `rm -rf` before the agent runs them; it's written in Rust, nearly invisible, configurable, and blocked commands can be approved manually from the CLI. Auto approval still relies on model judgment, so Claude Code wired to other models needs this safety net even more.
3. **Data says skills move developer output more than switching models**: citing Jellyfish's study of about 50,000 engineers at 447 companies, the tool explains under 1% of weekly merged PRs and switching between Opus, Sonnet or GPT stays within noise, while engineer-weeks with 30+ skill runs merged about 30% more PRs. Suggestion: turn the three things you explain to your agent most (review checklist, release steps, test command) into skills, and read any skill before installing it. https://x.com/russano/status/2113441475056841132
> [zh] **数据显示：用好 skill 比换模型更能提升产出**：引用 Jellyfish 对 447 家公司约 5 万名工程师的研究，工具本身只能解释不到 1% 的每周合并 PR 数，在 Opus、Sonnet、GPT 之间切换的差别都在噪声内；而一周跑 30 次以上 skill 的工程师，合并 PR 多约 30%。建议把最常跟 agent 解释的三件事（代码审查清单、发版步骤、测试命令）写成 skill，装别人的 skill 前先读一遍。
4. **不写代码用 Claude Code 和 Codex 干了半年，总结 8 条规矩**：一个项目只留一份交接文件，接手的 agent 先读、阶段结束写回；交接里的「已完成」不能直接信（可能是额度中断），先核对真实文件；改正式文件前先备份，删除、批量移动、覆盖必须人点头；能用脚本做的不让模型做，只给本次任务需要的文件；事实、自己的判断和 AI 推断分开标。https://x.com/Chengzhaoran/status/2113483552868143405
> [en] **Eight rules from six months of using Claude Code and Codex without writing code**: keep one handoff file per project that each agent reads first and updates after every phase; don't trust "done" in the handoff (it may have been a quota cutoff), check the real files; back up before editing important files, and require human approval for deletes, bulk moves and overwrites; let scripts do what scripts can and give the model only the files this task needs; label facts, your own judgment and AI inferences separately.
