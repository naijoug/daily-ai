## AI 热点
1. **微软：国家级黑客用开源 AI 渗透框架 ARTEX 自动化攻击，ConnectWise 供应链事件也是它干的**：微软安全博客说，与中国国家利益相关的组织 Storm-0940 从 9 月起用 ARTEX（GitHub 上开源的 agentic AI 渗透测试框架，把多个 LLM agent 串起来，从侦察一路跑到窃取数据，几乎不用人工）攻击全球数百家机构；有多起从选定目标到拿到云上特权访问不到 3 小时。它滥用 ConnectWise 备份与管理应用早已获授权的凭据登录 Microsoft 365 租户，不经过用户交互登录，也就绕过了 MFA；进去后通过 Microsoft Graph 做侦察、给其他应用加凭据、尝试提权（rohanpaul 摘要提到其中一个应用给自己授予了全局管理员）。大部分尝试仍然失败，例如一次密码喷洒 15 万多次全部失败；成功登录也不等于数据已被窃取。用 ConnectWise 或给第三方应用授权过 M365 的团队，按微软建议检查 10 月 15 日以来的服务主体登录、应用凭据和权限变更。https://www.microsoft.com/en-us/security/blog/2026/10/21/storm-0940-uses-artex-agentic-ai-connectwise-supply-chain-compromise/ ｜ https://x.com/rohanpaul_ai/status/2113113477552169349 ｜ https://thehackernews.com/2026/10/china-linked-hackers-use-artex-ai.html

5. **Nathan Lambert 哈佛讲座：开源模型的现状**：他认为开源模型落后闭源前沿约 3–5 个月，差距还在缩小；性能、下载量、论文引用三项中国开源模型都领先，美国开源模型又比中国落后 3–4 个月。他认为「蒸馏」被高估了：公开研究里看不到用推理过程做 SFT 有巨大提升，现在强化学习的算力也已经超过预训练。美国真正持久的优势是算力，前五家实验室的总算力平均是中国前五家的 16 倍。他还认为禁止开源挡不住坏人，只会伤害经济，建议由国家统一风险标准，按模型评估「额外风险」。讲义全文公开。https://natolambert.com/slides/2026/harvard/lecture.html ｜ https://x.com/shao__meng/status/2113092271503818988

## 有趣用法和干货
1. **Cloudflare 把 AI 代码审查单次成本从 2.43 美元降到 0.77 美元（-68%）**：审查耗时中位数从 4 分 9 秒降到 1 分 32 秒，代码质量类发现被作者采纳的比例反而从 34% 升到 59%。账单里缓存写入占 43%、缓存读取占 34%，输出只占 23%，所以钱主要花在重复的上下文上。省下的钱约 4 成来自工程改动：把各仓库共用的 11k–21k token 工具定义和系统提示拆成独立的缓存前缀（原来跟工作目录、日期拼成一个块，首个请求的缓存命中率只有 14%–26%）；三个审查角色共用同一前缀，一个写缓存，其余等它写完再读；去掉子 agent 用不上的工具；改成并行读文件；复审时跳过没有新内容的角色；结论发出后不再多跑一轮写总结。其余约 6 成来自换模型和调推理强度：协调角色用 Opus 5.5 medium，Sonnet 5.5 单价和 Sonnet 5 一样，但 token 用量少得多，成本低 47%–62%。代码质量角色用 high effort 只贵约 2 美分，严重和警告级发现多 58%；性能、安全角色在 medium 下确实漏掉了问题，下一步测 high。自己跑 agent 的团队可以照着逐项排查。https://blog.cloudflare.com/obsessive-inference-optimization ｜ https://x.com/shao__meng/status/2113098764324159608
2. **AgentReady：让网站能被 AI agent 用的开放规范，只有两件事真会让 agent 失败**：ora 联合 Vercel、Stripe、Auth0、Mintlify、Tavily 等发布（MIT 许可）。受控实验里，同一个文档站用 19 种配置提供，只有「答案只在 JS 渲染后才出现」和「对 agent 返回 403」会导致拿不到答案；llms.txt、JSON-LD、sitemap、Markdown 镜像都不改变结果。agent 主要靠页面上的链接找到 llms.txt 和 openapi.json，不会去猜路径；读不到官网时，它转而用第三方页面作答，回答里完全没有用户要问的事实的概率是正常情况的 3.7 倍。规范按「找到、读取、操作」三步分出 MUST/SHOULD/MAY：MUST 包括 robots 放行 agent、答案出现在初始 HTML 里、返回真实的 HTTP 状态码、至少提供 MCP 服务器或 CLI 之一。https://ora.ai/blog/agentready-launch ｜ https://x.com/shao__meng/status/2113084778673287480
3. **Stanford CS 329Z 第 9 讲：agent 系统优化方法怎么选**：前提是数据、系统、评估指标三样都有。先做便宜、省样本的上下文优化（少样本示例挑选与排序、DSPy/MIPROv2、TextGrad、GEPA）；上下文优化不够、想把能力蒸馏到小模型、或 prompt 越写越长时，再改权重（教师模型的轨迹做 SFT、GRPO 强化学习、on-policy 蒸馏）；也可以让 agent 自己做优化（Darwin Gödel Machine、Meta-Harness、karpathy 的 autoresearch），但这时最需要把控的是评估指标本身，防止它钻空子。BetterTogether 的结论是，有时最好的顺序是先调 prompt、再调权重、最后再调一次 prompt。讲义 PDF 可直接下载。https://web.stanford.edu/class/cs329z/slides/lecture09.pdf ｜ https://x.com/shao__meng/status/2113105750818164882
4. **装别人分享的 skill 之前，先用 NVIDIA SkillSpector 扫一遍**：这是 NVIDIA 在自家 skill 目录上架前用的开源扫描器（Apache 2.0，今年 3 月开源，现在 2 万多星，今天在 X 上又被大量转发）。它检查 17 类、71 种攻击模式，包括提示注入、数据外泄、提权、被投毒的 MCP 工具等，给每个 skill 打 0–100 的风险分并给出建议；支持 Claude Code、Codex、Gemini CLI 的 skill，可以扫 GitHub 仓库、URL、zip 包或本地目录。用法是 `uv tool install git+https://github.com/NVIDIA/skillspector.git` 安装，再运行 `skillspector scan ./the-skill/ --no-llm` 做不调用模型的快速扫描，需要时再开 AI 深度审查。原帖引用的分析是：31,132 个 agent skill 里 26.1% 有漏洞、5.2% 疑似恶意。https://github.com/NVIDIA/skillspector ｜ https://x.com/RoundtableSpace/status/2113114370406293672
