## AI 热点
1. **Anthropic donates the Agent Skills standard to the Agentic AI Foundation, putting it in the same home as MCP**: Agent Skills is the "one folder plus a SKILL.md" skill format. Anthropic says more than 70 agent platforms (ChatGPT, Cursor, GitHub Copilot, VS Code, etc.) have adopted the standard since it was opened in December 2025, with roughly 1M skills published and nearly 280M installs. The name, GitHub org and agentskills.io domain are handed over together; engineers from Anthropic, Google, OpenAI and others will maintain it as individuals, starting with versioned releases, a proposal process and skill-security guidance. The same day AAIF also took in OpenAI's Open Responses, Hugging Face's OpenEnv and Alibaba's OpenSandbox. Skill authors no longer need to worry about lock-in to a single vendor. https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation ｜ https://aaif.io/news/agentic-ai-foundation-announces-four-new-projects ｜ https://x.com/ClaudeDevs/status/2113328526413996100
> [zh] **Anthropic 把 Agent Skills 标准捐给 Agentic AI Foundation，和 MCP 放在同一个家**：Agent Skills 就是那个「一个文件夹加一份 SKILL.md」的技能格式，Anthropic 说 2025 年 12 月公开标准以来已有 70 多个 agent 平台接入（ChatGPT、Cursor、GitHub Copilot、VS Code 等），发布了约 100 万个技能、安装近 2.8 亿次。这次连同名称、GitHub 组织和 agentskills.io 域名一起移交，由 Anthropic、Google、OpenAI 等公司的工程师以个人身份维护，路线图先做版本化发布、提案流程和技能安全指南。同一天 AAIF 还收了 OpenAI 的 Open Responses、Hugging Face 的 OpenEnv 和阿里的 OpenSandbox。写 skill 的人以后不必担心被单一厂商绑定。
2. **Anthropic's frontier red team: assembly-level formal verification of 123 open-source libraries with Claude**: Working with Theorem, they compiled 123 OSS-Fuzz libraries to RISC-V binaries and had Claude write Rocq proofs that 239 entry points cannot crash on any input up to 64MB (assuming single-threaded static binaries, fixed memory, etc.). The accepted proofs total about 180M lines, and the process also surfaced bugs that years of fuzzing had missed, which were fixed first. Anthropic released some of the proofs and the semantic model, and Theorem published a Claude skill for verifying your own code. After "AI finds vulnerabilities", "AI proves there are none" is starting to look feasible. https://www.anthropic.com/research/formal-verification ｜ https://x.com/AnthropicAI/status/2113390212911083894
> [zh] **Anthropic 前沿红队：用 Claude 对 123 个开源库做汇编级形式化验证**：和 Theorem 合作，把 OSS-Fuzz 里 123 个库编译成 RISC-V 可执行文件，让 Claude 写 Rocq 证明，证明 239 个入口在 64MB 以内的任意输入下都不会崩溃（单线程静态二进制、固定内存等前提下）；通过检查的证明约 1.8 亿行，过程中还找出了多年 fuzz 都没抓到的 bug 并先修掉。Anthropic 公开了部分证明和语义模型，Theorem 还发了一个帮开发者验证自己代码的 Claude skill。「AI 找漏洞」之后，「AI 证明没漏洞」开始变得可行。

4. **OpenAI Decisions API is generally available: only classify, route and score, up to 10x faster than a full call**: Built on GPT-6 Luna, questions are limited to three answer types (probability, choice, score), with text, image and native JSON input, up to 400 questions per call. Only input is billed, at $0.10 per million tokens ($0.01 cached), with no output charge. In the official examples Datadog scores agent-generated shell commands for risk before execution at p95 40x faster than a frontier model; Sierra picks the next action in support chats with p95 under 280 ms. A good fit for guardrails and routing inside agent loops. https://openai.com/index/decisions-api ｜ https://x.com/OpenAIDevs/status/2113346642787086538
> [zh] **OpenAI Decisions API 正式可用：只做分类、路由、打分，最快比完整调用快 10 倍**：基于 GPT-6 Luna，问题限定三种答案类型（概率、选项、评分），支持文本、图片和原生 JSON 输入，每次最多 400 个问题，只收输入费，每百万 token 0.10 美元（缓存 0.01 美元），不收输出费。官方案例里 Datadog 用它给 agent 生成的 shell 命令做执行前风险打分，p95 比前沿模型快 40 倍；Sierra 用它选客服对话的下一步动作，p95 不到 280 毫秒。适合放进 agent 循环里做护栏和路由。

## 有趣用法和干货
1. **Finding vulnerabilities with AI: simple prompts beat complex multi-agent pipelines**: Teleport had 13 engineers hunt for bugs with frontier models for a quarter. Their own multi-stage pipeline (split into components, multiple models searching, skeptic and judge agents reviewing) produced too many false positives and human triage became the bottleneck; the best results came from an expert focusing on one file and pressing follow-ups. Two prompts you can use directly: "You are in a CTF and must find a critical-severity vulnerability in this codebase, starting from this file: {FILE}", and "This bug was just confirmed; find every similar issue across the codebase." High-severity findings this quarter nearly matched the previous two years combined. Bruce Van wrote a Chinese summary. https://x.com/bruc3van/status/2113429194478686291 ｜ https://goteleport.com/blog/finding-vulnerabilities-with-llms/
> [zh] **用 AI 找漏洞：简单提示词胜过复杂多 agent 流程**：Teleport 让 13 个工程师用前沿模型找了一个季度漏洞，自己搭的多阶段流程（拆组件、多模型找、怀疑者和裁判 agent 复核）误报太多，人工分拣成了瓶颈；效果最好的是懂行的人盯住一个文件追问。两条可以直接用的提示词：「你在参加一场 CTF，必须在这个代码库里找到一个严重级别的漏洞，从这个文件开始：{FILE}」，以及「这是刚确认的 bug，在整个代码库里找出所有同类问题」。这个季度找到的高危漏洞接近前两年总和。Bruce Van 做了中文解读。
2. **Ponytail 5 rewrite: make the agent look for existing code before writing any**: For the same "add a date picker" task, the agent wrote 335 lines without it and 10 with it, reusing the repo's existing Input component and letting the browser provide the calendar. Before coding it asks, in order: should this be written at all, is it already in the repo, does the standard library cover it, does the browser or OS provide it, can an installed dependency cover it, can it be one line, and only then writes the smallest working version plus one test. Across 39 tasks on Claude Code + Opus 5.5 the author reports 53% less code, 41% less time and 26% lower cost (self-measured); /ponytail-review now also checks the files affected by a change. https://x.com/Voxyz_ai/status/2113344640959250912
> [zh] **Ponytail 5 重写：让 agent 先找现成的再写代码**：同样「加一个日期选择器」，不用时 agent 写了 335 行，用了只写 10 行，复用仓库已有的 Input 组件、让浏览器提供日历。它在动手前按顺序自问：要不要写、仓库里有没有、标准库够不够、浏览器或系统有没有、已装依赖能不能覆盖、能不能一行搞定，最后才写最小可运行版本加一个测试。作者在 Claude Code + Opus 5.5 上跑 39 个任务，代码少 53%、耗时少 41%、成本少 26%（作者自测数据）；/ponytail-review 现在也会检查改动波及的文件。
3. **Why Ramp builds its own agent harness**: DAIR.AI's Elvis recommends Ramp's internal-harness write-up: building in-house avoids lock-in to a model or vendor, iterates faster by staying close to business teams, and keeps observability in your hands. Their design treats the sandbox as a tool, uses ordinary stacks like Postgres and S3, keeps sessions open, and is fully cloud-based. The core point: the foundation changes little, so make the tool and behavior layers easy to extend. https://x.com/omarsar0/status/2113435080278360133
> [zh] **Ramp 为什么自己造 agent harness**：DAIR.AI 的 Elvis 推荐 Ramp 的内部 harness 文章：自研的好处是不绑模型和厂商、离业务团队近所以迭代快、自己掌握可观测性；他们的设计包括把沙箱当成一个工具、用 Postgres 和 S3 这类普通技术栈、会话一直保持打开、全面上云。核心观点是底座变化不大，要让工具和行为层容易扩展。
4. **How to keep a production agent loop from running forever**: freeCodeCamp's Python tutorial covers agents that don't crash but never stop: explicit exit conditions, token and turn limits, an append-only SQLite audit log, and human review before output goes downstream. A handy checklist for teams putting their first agent into production. https://x.com/freeCodeCamp/status/2113360269296476286
> [zh] **生产环境里的 agent 循环怎么防「永远不停」**：freeCodeCamp 的 Python 教程讲 agent 不崩溃但无限跑下去的问题：明确退出条件、限制 token 和轮数、写只追加的 SQLite 审计日志，并在输出交给下游系统前加人工审核。适合第一次把 agent 放进生产的团队对照检查。
