## AI 热点
1. OpenAI API 里悄悄出现三个没公布的模型：aurora-red-alpha、aurora-green-alpha、aurora-blue-alpha（约 11 点被 Lisan al Gaib 和 Andrew Curran 先后发现，Curran 帖近千赞）。OpenAI 没有公告、文档或定价，有人测 aurora-red-alpha 返回 503。今年 2 月 OpenRouter 上的匿名模型 aurora-alpha 后来被普遍认为是 GPT-5.3-Codex-Spark，所以圈里猜这次是编程专用或高速推理版。alpha 模型先别进生产。https://x.com/AndrewCurran_/status/2111656899338973391 / https://x.com/scaling01/status/2111653358322729401
2. Google Research 开源 Harness²：不改模型权重，只自动调整 agent 周围的 8 个组件（系统提示词、护栏、记忆、工具说明、子 agent、skills、脚本、插件）来提升表现。每个任务先"提出改动、在同一任务上试跑、对比行为后合成新配置"，不需要标准答案；成功经验沉淀进跨任务的改进库。论文说一步就让 GLM-5 和 Gemini 3.5 Flash 在 WorkBuddy-Bench 上最高涨 11.5 分，执行器支持 OpenCode 和 Codex（--substrate cx），本周 GitHub 涨了约 1.5k star。https://x.com/Gorden_Sun/status/2111652432761786872 / https://github.com/google-research/harness2 / https://arxiv.org/html/2610.14224

DeepSeek-V4.1-Flash-1017 后续：腾讯 WorkBuddy 国际版限时免费用到 10/31（国内版暂无）；有开发者算账说 Claude 和 OpenAI 的 API 联网搜索是每千次 10 美元另加 token，DeepSeek Search 每千次 0.75 美元，便宜十几倍。中文圈对它评价两极：有人说接近 Kimi K3、强过 Gemini 4 Argon，也有人批评国产模型总拿 API 单价说事。https://x.com/shao__meng/status/2111651905177092577 / https://x.com/HimanshuRawal05/status/2111659932823196134 / https://x.com/berryxia/status/2111652661078741299

## 有趣用法和干货
1. 像管钱包一样管 API key（Bojie Li）：他本人和服务的公司都被盗刷过多次、每次损失几千美元。做法是厂商 key 只放在一台仅内网可访问的 LiteLLM 网关上，所有服务、CI、编码 agent 都走网关；每个 key 配一个 canary 字符串，各服务在 system prompt 里预埋，网关发现请求缺 canary 就拒绝并告警，用来识别 key 被复制滥用；开发测试另发不查 canary、额度很小的 key。他还提醒 AI 部署的服务容易误监听 0.0.0.0 把家目录的 key 暴露出去。刚经历 OpenCode Console 泄露，值得照着做。https://x.com/bojie_li/status/2111666060281934142
2. 一泽 Eze 的 Web Access Skill 更新后支持 Grok Bot：让 agent 用你本机已登录的 Chromium 系浏览器（含 Arc）做联网和采集，适合要本机登录态、非机房 IP 的任务；不依赖截图所以省 token，每探索一个网站就自动沉淀成站点 skill，下次访问更快，还能按需查本机书签和历史；Codex、Claude Code 等一次安装都能用，GitHub 约 9.2k star。https://x.com/eze_is_1/status/2111655085910696119
3. 给 agent 接上便宜的联网搜索（向阳乔木）：他把 DeepSeek 新开放的 Search 和 Fetch API（每千次 5 元）包成了 skill，用 npx skills add 一行装上，据说还能读公众号文章，可以替代贵的内置搜索。https://x.com/vista8/status/2111676128121491902
4. Graphify：在编码 agent 动手前先给整个代码库建本地知识图谱，让 Claude Code、Codex、Cursor 顺着架构关系追调用，而不是一个个文件读，适合大仓库省上下文。https://x.com/RoundtableSpace/status/2111642169421299906
