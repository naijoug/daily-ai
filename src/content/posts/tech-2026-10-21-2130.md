## 新产品 / 开源
1. **tsrs: Cloudflare and VoidZero port the TypeScript compiler to Rust**: a faithful port made in cooperation with the TypeScript team, not a fork; language design is still decided officially, and the project is incubated in the Oxc toolchain. The company says that at the same number of type-check workers it is up to 8x faster than TS 7.0 with about 70% less memory, and some optimizations have already been contributed back to the TS 7.1 beta. The main reason for choosing Rust over Go is that compiling to WebAssembly doesn't need a garbage collector, making it easy to run a full dev environment in browsers and Workers. The post also says plainly that frontier models can now do such a large-scale port essentially independently within days. You can try the experimental version with `npx tsrs`. [Cloudflare blog](https://blog.cloudflare.com/typescript-rust-port/) ｜ [HN discussion](https://news.ycombinator.com/item?id=50165953) (422 points. Someone counts three ports now: tsrs, tsgo-rs and `bun check`; people with large codebases look forward to the speedup but are uneasy about the author's claim of "not writing a single line of code")
> [zh] **tsrs：Cloudflare 和 VoidZero 把 TypeScript 编译器移植到 Rust**：这是在 TypeScript 团队配合下做的忠实移植，不是 fork，语言设计仍由官方决定，项目放在 Oxc 工具链里孵化。官方说在类型检查 worker 数相同的情况下，它比 TS 7.0 快最多 8 倍、内存少约 70%，还有一部分优化已经回馈给了 TS 7.1 beta。选 Rust 而不是 Go 的主要原因是编译到 WebAssembly 时不用带垃圾回收器，方便在浏览器和 Workers 里跑完整的开发环境。文中也直说，现在前沿模型几天内就能基本独立完成这种大规模移植。现在可以 `npx tsrs` 试用实验版。[Cloudflare 博客](https://blog.cloudflare.com/typescript-rust-port/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50165953)（422 分。有人数出现在已经有 tsrs、tsgo-rs、`bun check` 三个移植版本；用大型代码库的人很期待提速，但对作者「一行代码都没写」的说法不太舒服）
2. **Mercury 3: a diffusion LLM reaches the GPT-6 Luna tier**: Inception Labs says Mercury 3 produces 1,068 tokens per second on NVIDIA GPUs, 4–8x faster than comparable GPT-6 Luna and Claude Haiku 5.5, with equal or better quality. 1M context, priced at $0.2 per million input tokens and $0.7 output, half price during launch. It has over 40x the parameters of Mercury 1, and the company concludes diffusion models also obey scaling laws. A partner tested it on 50 real web navigation tasks from Mind2Web with a 50% completion rate, higher than GPT-6.1 Sol. Browser agents wait for the model at every step, so latency-sensitive scenarios like this are worth trying. 4. **cloudflare/security-audit-skill: have a coding agent run a security audit by process**: up nearly 2,000 stars on GitHub Trending today, and Cloudflare's internal vulnerability-hunting system grew out of this skill. The audit has six steps: first reconnaissance, mapping architecture and trust boundaries and building a coverage ledger; then dispatching mutually isolated agents against the ledger to find issues; each suspicious point goes to a fresh agent that specifically tries to disprove it; results are written as schema-validated JSON with "confirmed / needs verification / rejected"; finally another batch of agents goes back to the source to check before generating the report. The bundled attack categories cover LLM prompt injection, supply chain, cloud configuration and more. A good reference for teams checking PHP and certificate issues these days. [GitHub](https://github.com/cloudflare/security-audit-skill)
> [zh] **cloudflare/security-audit-skill：让 coding agent 按流程做安全审计**：今天 GitHub Trending 上涨了近 2,000 星，Cloudflare 内部的漏洞挖掘系统就是从这个 skill 发展出来的。审计分六步：先侦察，画出架构、信任边界，建一份覆盖台账；再按台账派互相隔离的 agent 去找问题；每个可疑点交给新开的 agent，专门尝试推翻它；结果按「确认 / 待验证 / 驳回」写成带 schema 校验的 JSON；最后由另一批 agent 回到源码核对，再生成报告。附带的攻击类别覆盖 LLM 提示注入、供应链、云配置等。对这几天要排查 PHP 和证书问题的团队来说，正好可以参考。
5. **Laminar flow-1: an RL-trained model specialized in finding errors in agent trajectories (Launch HN)**: the author's view is that agent failures are often silent, like clicking the wrong button or citing the wrong document with every call showing success, so you can't catch them by looking at final output alone. flow-1 treats a trajectory as a code repository and each span as a file, grepping and reading like a coding agent. On their own 523 hard trajectories, detection F1 is 0.835, slightly above GPT-6-sol (0.816) and below Claude Opus 5 (0.890), but it analyzes 23x as many trajectories per dollar as Sol, about $0.001 each, so online trajectories can all be checked without sampling. [Blog](https://laminar.sh/blog/flow-1) ｜ [HN discussion](https://news.ycombinator.com/item?id=50154029) (a comment notes the more common failure is a tool returning normally but with an untrustworthy result, such as stale cached data or injected instructions hidden in a web page)
> [zh] **Laminar flow-1：用强化学习训练、专门从 agent 轨迹里找错的模型（Launch HN）**：作者的观点是，agent 的失败往往是隐性的，比如点错按钮、引错文档，每次调用都显示成功，所以只看最终输出是查不出来的。flow-1 把一条轨迹当成代码仓库、每个 span 当成一个文件，像 coding agent 一样边 grep 边读。在他们自己的 523 条难轨迹上，检测 F1 是 0.835，略高于 GPT-6-sol（0.816），低于 Claude Opus 5（0.890），但每美元能分析的轨迹数是 Sol 的 23 倍，每条约 0.001 美元，所以线上轨迹可以全部检查、不用抽样。[博客](https://laminar.sh/blog/flow-1) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50154029)（有评论指出更常见的失败是工具正常返回了，但结果本身不可信，比如缓存数据过期，或者网页里藏着注入指令）

2. **The private keys of eMudhra's 8 intermediate CAs are only one byte**: Indian CA eMudhra has 6 TLS-issuing CAs and 2 code-signing CAs, and the first 47 bytes of their P-384 private keys are all zero, the actual values being single- to triple-digit numbers like 4, 56 and 115. Scott Helme, starting from the public certificates, computed all of them on a laptop in under a second. These CAs were also cross-signed by Sectigo's AAA root, so in theory they can issue trusted certificates for any website.
