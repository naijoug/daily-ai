3. The US Department of Homeland Security (DHS) ordered civilian federal agencies to remove DeepSeek and "third-party products and services built on DeepSeek" and banned procurement. The order was signed July 24, made public October 19 and published in the Federal Register October 20; defense and intelligence systems are excluded. Rohan Paul notes that weights running on US servers aren't exempt, and vendors selling software to government will need to state which open-weights models their products use. Cross-checked against MeriTalk, WSJ and others. https://x.com/rohanpaul_ai/status/2112265351492972953 ｜ https://www.meritalk.com/articles/dhs-orders-civilian-agencies-to-remove-deepseek-ai-products/

## 有趣用法和干货
1. Before launch, have 4 subagents act as first-time users (Vox): in Claude Code, have Opus 5.5 dispatch 4 subagents to take turns using the browser from landing page to first success: an impatient random clicker, a skeptic who reads pricing and privacy terms first, a mobile user on a 375px screen and slow 3G, and a saboteur who fills forms randomly and mashes buttons. Places where they get stuck are screenshotted into `qa/first-users/` and ranked by how many hit them; after fixing, 4 fresh subagents that haven't seen the issue list retest and produce a before/after comparison. The original post includes a full copy-paste prompt (run only locally or in preview, with test email and test payments). Very handy as a pre-release walkthrough. https://x.com/Voxyz_ai/status/2112302775547679169
> [zh] 上线前让 4 个 subagent 扮演第一次来的用户（Vox）：在 Claude Code 里让 Opus 5.5 派 4 个 subagent 轮流用浏览器从落地页走到「首次成功」：没耐心乱点的、先读定价和隐私条款的怀疑派、375px 屏 + 慢速 3G 的手机用户、乱填表单狂点按钮的破坏者。卡住的地方截图存进 `qa/first-users/`，按多少人踩到排序；修完再派 4 个没看过问题表的新 subagent 复测，出前后对比。原帖附了完整可复制的提示词（要求只在本地或预览环境跑、用测试邮箱和测试支付）。做产品发版前的走查很实用。
2. Run DeepSeek V4.1 Flash locally (Unsloth): Unsloth built a llama.cpp implementation and dynamic GGUFs; the 1-bit version shrinks from 508GB to 250GB while keeping about 88.2% accuracy, runnable on machines with 128GB+ RAM. Daniel Han adds that the engram/PLE part can switch between MXFP8, Q6_K, Q5_K and IQ4_NL (Q6_K is roughly equal to MXFP8), and the engram can be streamed entirely from disk. Follow the official guide if you want to self-host the strongest open model on a big-memory Mac or workstation. https://x.com/UnslothAI/status/2112212605930778830 ｜ https://x.com/danielhanchen/status/2112215677214044393 ｜ https://unsloth.ai/docs/models/deepseek-v4.1-flash
> [zh] 本地跑 DeepSeek V4.1 Flash（Unsloth）：Unsloth 做了 llama.cpp 实现和动态 GGUF，1-bit 版本从 508GB 压到 250GB、保留约 88.2% 准确率，128GB+ 内存的机器能跑；Daniel Han 补充 engram/PLE 部分可在 MXFP8、Q6_K、Q5_K、IQ4_NL 间切换（Q6_K 约等于 MXFP8），而且 engram 可以完全从磁盘流式读取。想在大内存 Mac/工作站上自托管最强开源模型的可以照着官方指南来。
3. For an agent knowledge base, try a Markdown index before vector retrieval (Paul Iusztin): his LLM wiki uses a Markdown index page listing each page's title and blurb; the agent reads the index, picks relevant pages and follows links as needed, with no embeddings. In another post he says the hardest part of a knowledge graph is deciding which concepts deserve their own node, otherwise a node per mentioned concept is all noise, and he set a filtering rule (details in the original post). A good reference for giving Claude Code/Codex project documentation. https://x.com/pauliusztin_/status/2112280122774732905 ｜ https://x.com/pauliusztin_/status/2112219726462042263
> [zh] 给 agent 做知识库，先试 Markdown 索引再上向量检索（Paul Iusztin）：他的 LLM wiki 用 Markdown 索引页列出各页标题和简介，agent 先读索引、挑相关页面、需要时顺着链接继续读，不用 embedding。他另一条帖子说，做知识图谱最难的是决定哪些概念值得单独成节点，否则每个提到的概念都建节点会全是噪音，他为此定了一条筛选规则（细节见原帖）。对给 Claude Code/Codex 配项目文档很好借鉴。
4. Pitfalls of cross-organization agent collaboration (Salesforce paper, via Rohan Paul): across 488 scenarios and 2,500+ agent-to-agent sessions (Claude Code, Codex and Cursor each in separate sandboxes), 20 failure modes emerged: no agent proactively re-fetched documents to verify the other side's claims, and they basically only contacted each other when prompted; a $24,000 service-dispute settlement passed all 10 outcome checks, yet the vendor agent leaked confidential details. Takeaway: when your agent deals with external agents, write verification into the protocol and score each separately by the party it represents. https://x.com/rohanpaul_ai/status/2112228442595013057
> [zh] 跨组织 agent 协作的坑（Salesforce 论文，Rohan Paul 转述）：在 488 个场景里跑了 2500+ 次 agent 对 agent 会话（Claude Code、Codex、Cursor 各在独立沙箱），归纳出 20 种失败模式：没有一个 agent 会主动重新拉文档核实对方的说法，基本只在提示要求时才联系对方；一个 2.4 万美元的服务纠纷和解通过了全部 10 项结果检查，但供应商 agent 泄露了机密细节。启示：你的 agent 要和外部 agent 打交道时，要把核验写进协议，并按它代表的那一方单独打分。
