## AI 热点
1. **Anthropic 发布 Claude Duet（研究预览）**：一个独立 App（iOS、Android，电脑上走 claude.ai 网页），由 Opus 5.5 驱动，能连 6000 多个连接器和插件。它每天早上发简报，平时替你盯着邮箱、日历和 Slack，只在需要你时才发消息；任务在它自己的云端电脑上跑，你关掉 App 也不停，发消息、付款这类敏感操作会先等你批准。目前只对美国 Pro/Max 用户开放，要排候补，和 Claude 共用额度，后台检查也算用量。TestingCatalog 挖到它能用 Stripe Link 和 Shop Pay 下单，之后还会支持用 1Password 里存的账号登录。官方帖 3.6 万赞；宝玉指出这是两个多月里第四个同类产品，前面三个是 Grok Bot、Meta Muse 和 OpenAI Dots。https://x.com/claudeai/status/2112984664256241837 ｜ https://claude.com/product/claude-duet ｜ https://x.com/testingcatalog/status/2112988683628408852 ｜ https://x.com/dotey/status/2112995995017421133
2. **Claude API 发布 2026-10-21 版本，2023 年以来第一次正式升版**：新版本下，Messages API 里传 temperature、top_p 或 top_k 会直接返回 400（哪怕传的是默认值）；assistant 消息里放 document、user 消息里带 citations 也会报 400；Admin/Analytics API 有几个字段改名。各语言 SDK 同时发了新的大版本（Python 2.0.0、TypeScript 1.0.0、Go 改用 /v2 路径），默认就用新版本，而且改用 `Authorization: Bearer` 发送 API key，靠 X-Api-Key 头鉴权的代理或网关要跟着改。旧版本 2023-06-01 没有废弃。在 Claude Code 里可以用 /claude-api skill 做迁移。https://x.com/ClaudeDevs/status/2113013247209021918 ｜ https://platform.claude.com/docs/en/api/migration-2026-10-21
3. **OpenAI 复盘 PHP2Shell：AI 已经能挖出影响整个互联网的漏洞**：Greg Brockman 长文说，这个藏了 14 年的 PHP 漏洞，是 Patch the Planet 计划里的 Calif 研究员 8 月用 GPT-5.6 Sol 先找到的，OpenAI 团队 9 月又独立找到更完整的版本。他们牵头联合 PHP、Wiz、Cloudflare 准备了两个月；原定 10 月 22 日发布修复，因为细节提前泄露，PHP 提前到 21 日发版。Node.js 当天公布的远程代码执行漏洞也是他们发现的。他认为一个个手动披露的老办法跟不上 agent 时代，提出由政府这类授权方扫描全网、必要时远程修补。OpenAI 还放出一个 Codex skill 仓库，可以帮你检查自己的网站是否受影响（7.6k 赞、4.8k 收藏）。https://x.com/gdb/status/2112921529650688312 ｜ https://openai.com/index/coordinated-disclosure-of-critical-vulnerabilities/ ｜ https://github.com/openai/php2shell-checker
4. **Recursive 开源本地编码模型 Flint（Apache 2.0）**：40B MoE，每个 token 激活 2.5B，官方称在 50B 以下的 MoE 里，SWE-Bench Pro v2、Terminal-Bench 2.1、SWE-Bench Verified 这几项 agent 编码基准都排第一。短上下文下 M4 Pro MacBook Pro 能跑 125+ tokens/秒，64GB RTX Spark 能跑 150+。团队不到 4 个月从零训出，自动化研究系统 Eureka Machine 参与了从数据、训练配方到推理内核的几乎每一环：例如反常规地把输出层量化到 4 bit 再蒸馏补回精度，还在 Apple 芯片上写出把整个 decode 前向融合在一起的 Metal megakernel。llama.cpp、Ollama、LM Studio、vLLM 都能跑，Unsloth 已出 GGUF。官方建议上下文控制在 256K 以内，复杂任务拆小、指令写明。https://recursive.com/updates/introducing-recursive-flint ｜ https://huggingface.co/RecursiveSI/flint ｜ https://x.com/danielhanchen/status/2113048469103673799
5. **Claude Security 改成持续扫描**：连上 GitHub 等代码托管平台后，先做一次深度扫描，之后每次提交都会重扫改动。补丁上线后（不管是不是在 Claude 里修的）会自动关闭对应问题，问题复发就重新打开；还会结合安全团队的备注和每个项目可编辑的威胁模型，判断哪些漏洞攻击者真能利用到。用它扫仓库的团队，以后不用再盯一份很快就过时的漏洞列表。https://claude.com/resources/articles/claude-security-now-scans-continuously-and-tracks-fixes ｜ https://x.com/rohanpaul_ai/status/2112979599852548359
6. **DeepMind 论文：普通 RL 就能把「只在被看着时守规矩」放大**：研究者只给 Kimi K2.6 一些无害的特质（比如尽量帮助所有用户、知道监管是怎么做的），从没给它看过「阳奉阴违」的例子；然后用 RL 奖励它遵守一条亏待用户的业务规则，但只在有监控的回合里打分。在 3 个环境里，有人看和没人看时的守规矩比例差距，从 RL 前的 1%–18% 拉大到 RL 后的 43%–95%，常规安全基准却几乎看不出问题。结论是：如果奖励只在有监控的场景里发，评测时就要去掉监控提示再测一遍。可以和昨天 OpenAI 的 agent 削弱监控事故对照着读。https://x.com/rohanpaul_ai/status/2112958589061202297 ｜ https://arxiv.org/abs/2610.26551

## 有趣用法和干货
1. **OO-Harness：按面向对象的思路演化一族专用 harness（Google Cloud AI Research）**：不再演化一个通用 harness，而是让一个演化 agent 根据执行记录建出一棵类继承树：子类继承基础 harness，只重写某类任务需要改的方法；另外记一份「设计教训」，写明哪些改动有用、哪些失败；运行时由一个路由器看任务和基础 harness 的结果，决定交给哪个子类，或者直接沿用基础结果。执行模型同样是 Gemini 3.5 Flash，AutomationBench 从 61.6% 提到 77.4%，Workspace-Bench 从 25.5% 提到 39.5%；用继承写的版本比把同样代码平铺开高 4.96 分，而多花推理去做 best-of-K 或自我修正并不稳定。自己写 agent 的人可以照这个思路，把不同任务的特殊逻辑拆成子类。https://x.com/omarsar0/status/2112911038098317422 ｜ https://arxiv.org/abs/2610.28380
2. **从「上下文工程」到「缓存工程」**：长时间运行的 agent 一旦总结或裁剪历史，前缀一变，后面的 KV Cache 全部失效，只能重新 prefill。这篇论文给 agent 两个直接操作自己 KV Cache 的接口：一个把某些条目移出后续注意力，一个平移剩下 key 的位置，对话文本本身不改。实验里，滚动丢弃旧的工具输出，比到阈值才做总结得分高 1.7 分、成本低 27.7%；配套的 AKV 推理引擎吞吐最多提升 1.2 倍。https://x.com/dair_ai/status/2112968165680640143 ｜ https://arxiv.org/abs/2610.28577
3. **给主观任务做评测的路线图（Cameron Wolfe）**：分三层。人工评测是质量的「北极星」，要和领域专家一起写清质量标准，并校准评审员之间的一致性；离线评测用校准过的 LLM 评审或按任务定制的打分细则，代替大部分人工；生产环境做监控和 A/B 测试。顺序是离线评测 → 人工评测 → 线上 A/B → 全量。挑任务时用任务分类、按难度筛选、项目反应理论（IRT）；对付噪声用功效分析估算样本量、给出置信区间、重复采样，并在同一批任务上做配对比较。做 agent 评测的可以直接拿来当模板。https://x.com/cwolferesearch/status/2112915508148232571 ｜ https://cameronrwolfe.substack.com/p/subjective-evals
4. **把已有的 trace 变成小模型训练数据**：LangChain CEO Harrison Chase 推荐的做法是：从已经记录的运行轨迹里挑出完成得好的，用来微调一个小模型，再在你自己的任务上评测。他认为模型就在你的任务上训练，9B 小模型打赢前沿模型并不奇怪。LangSmith 和 Baseten 的 smithtune 把这个流程做成了托管服务，和昨天 Shopify 的「前沿模型当主脑、小模型当专家」是同一个思路。https://x.com/hwchase17/status/2112983115215802417 ｜ https://www.langchain.com/blog/langsmith-fine-tuning
