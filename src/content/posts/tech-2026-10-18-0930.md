## 新产品 / 开源
1. **Pele：Obsidian 团队开源的 Mermaid 渲染器**：把 Mermaid 文本直接渲染成 SVG，同步执行、零运行时依赖，颜色和字体用 CSS 变量控制，切换主题不用重新渲染；官网的对比是 gzip 后 230 kB 对 Mermaid.js 的 1.6 MB，单图渲染 0.05–0.3 ms 对 6–82 ms，窄屏会重新排版而不是整体缩放。支持 Mermaid 12.1.0 内置的全部图表类型，解析器用 Mermaid 自己的测试用例和差分模糊测试验证过，MIT 许可，`npm install pele` 即可用。在文档站、笔记应用或 Agent 输出里嵌流程图的人可以看看。[官网](https://pele.run/) ｜ [GitHub](https://github.com/obsidianmd/pele) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50132193)（230 分：有人吐槽 Mermaid 真正的痛点是复杂图的布局很差，样式反倒是小问题；也有人认为不依赖浏览器环境就能出 SVG，方便嵌到更多地方）
2. **tsc-ts（Vercel Labs）**：把 TypeScript 7.0.2 的 Go 版编译器（tsgo）逐模块移植回 TypeScript，再用 scriptc 编译成原生可执行文件。README 列出扫描器、解析器、类型检查、JS 和 .d.ts 输出、`--build` 增量编译等各部分，都在 TypeScript 约 12,500 个测试文件上和 tsgo 逐项比对一致，还提供和 `tsc --api` 相同的 API 服务。目前是实验项目，Apache 2.0。[GitHub](https://github.com/vercel-labs/tsc-ts) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50132911)（有人实测比 Go 版还快，但指出它其实是用 scriptc 支持的 TypeScript 子集写的，语义上还有些细微差异；也有人看不懂 tsgo 本来就是原生的，为什么还要再移植回来）
3. **esp32sim（Show HN）**：用 Rust 写的开源 ESP32 模拟器，覆盖 ESP32、S3（Xtensa）和 C3、C6（RISC-V），启动真实的掩码 ROM 和二级引导程序，跑不经修改的固件，还模拟了虚拟 Wi‑Fi 热点（WPA2、DHCP，可以 NAT 到真实网络）和几种屏幕。可以编译成 WebAssembly 在浏览器里跑，S3 已标为成熟，C3、C6 还是草稿，MIT 许可。作者最想知道嵌入式开发者要它支持到什么程度才愿意拿来做开发和 CI。[GitHub](https://github.com/mikroverk/esp32sim) ｜ [在线试玩](https://mikroverk.github.io/esp32sim/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50131189)（有人说 IoT 团队可以让移动端和后端在拿到硬件前就对着真实固件联调；也有人问它和 Wokwi 有什么区别，还有人嫌 README 的 AI 味太重）
4. **gopls 支持交互式重构**：Go 团队和 Dart 团队一起向 LSP 提了一个新能力，让语言服务器在改代码前可以弹窗问用户参数。于是「添加结构体标签」可以选 `json,yaml,db` 和 snake_case 等命名风格，「实现接口」可以搜索任意接口名并自动生成方法桩，跨文件、跨包移动声明（连同只被它用到的辅助声明一起搬，并清理 import）也在路上。gopls v0.24.0 和 VS Code Go 扩展 v0.56.0 已可用，Neovim、Emacs 有概念验证。这是 10 月 16 日的 Go 官方博客，之前没写过。[Go 博客](https://go.dev/blog/interactive-refactoring) ｜ [LSP 提案](https://github.com/microsoft/language-server-protocol/issues/1164)

## 科技新闻
1. **Codex 桌面版的 Crashpad 转储能把硬盘写满**：这个 6 月提交的 issue 今晚上了 HN。最新一条评论说，在当前的 ChatGPT.app 26.1007 版本上，两个 Crashpad 目录合计约 323 GB、400 多万个文件，磁盘只剩 1.4 GB，应用里没有任何提示。之前有人分析过原因：`browser_crashpad_handler` 启动时一个 Mach 端口调用失败就崩溃，而它又在监控自己，于是给自己写一份转储再重启，大约每秒一个、每天约 15 GB，`pending` 目录又没有大小上限。用 Mac 版的人可以先看看 `~/Library/Application Support/Codex/Crashpad/pending` 和 `com.openai.codex/web/Crashpad`，评论里有清空后把目录设为只读的临时办法。[GitHub issue](https://github.com/openai/codex/issues/25921) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50133231)（有人庆幸自己一开始就把这些 Agent 关在 Docker 里；也有人说每个 git worktree 都重复一份构建产物，磁盘压力同样大；还有人提醒 ChatGPT 应用设置里有个存储页能看占用）
2. **LWN 统计 Linux 7.2：AI 辅助提交和 Fixes 标签都在猛涨**：7.2 有 16,418 个非合并提交，是史上第二忙的版本，贡献者 2,652 人、新人 613 人，都创了纪录。带 Assisted-by 标签的提交有 1,111 个，7.1 只有 301 个，作者认为实际比例远高于此，因为很多人不标，甚至有维护者会删掉这个标签；另有 252 个补丁的 Reported-by 记在 AI 审查系统 Sashiko 名下，带 Fixes 标签的修复提交达到 4,830 个，曲线明显上翘。Corbet 的担心是，有些提交者可能并不完全理解自己交的补丁。这篇文章署名日期是 8 月 17 日，本时段上了 HN 首页。[LWN](https://lwn.net/Articles/1088776/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50132950)（有维护者说把 Agent 指向 bug 报告，复现、调试、修复它都能做完，人只管审；也有人指出这些数字没有对照组，很难算清 LLM 的真实影响）
3. **纳德拉：把所有 Agent 当作内部风险来管，Windows 要给 Agent 单独的身份**：Joanna Stern 的专访里，纳德拉说「我把所有 Agent，或者说所有模型，都当作内部风险」。Windows 正在改造：Agent 有和用户分开的身份，跑在隔离环境里，权限受限，由安全软件监控，Defender 会跟踪 Agent 的行为，越权时标记并叫停。他还演示了在 2,600 美元起、搭载 Nvidia RTX Spark 的 Surface Laptop Ultra 上用本地模型自己做的应用，强调本地加云端的混合模式。采访发布于 10 月 15 日，Techmeme 今早才收录。[The New Things](https://thenewthings.com/p/microsoft-ceo-on-rogue-ai-agents-super-laptops-and-clippy) ｜ [Techmeme](https://www.techmeme.com/261017/p20#a261017p20)
4. **JDK 28 的 JEP 清单**：目前定向到 JDK 28 的有 Valhalla 的值对象（预览）、JVM 严格字段初始化（预览）、简易 JSON API（孵化）、正式版结构化并发、提前编译机器码、ZGC 更快的启动预热和自适应堆大小、Shenandoah 默认启用分代模式、加密对象的 PEM 编码，另外 macOS/x64 移植被标记为弃用、准备移除。[OpenJDK](https://openjdk.org/projects/jdk/28/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50135379)（有人感慨 Java 这几年迭代明显加快，自己用 Kotlin 写服务端，但现代 Java 越来越够用；也有人不满新的 JSON API 不支持尾逗号和注释）
5. **Google 在 Willow 上验证「魔术态培育」，错误率降约 40 倍**：要做通用、可纠错的量子计算，需要大量「魔术态」，有估计说它可能占掉整台量子计算机 95% 的资源。Google 2024 年提出的培育方法相当于一个过滤器，这次在 Willow 处理器上实测，错误比不培育时少了约 40 倍，T 态逻辑保真度达到创纪录的 99.99%，还演示了把状态从距离 3 的色码移植到距离 5 的表面码，论文发在 Science。Google 也说还需要更大规模的验证。博客是 10 月 15 日的，本时段才在 Techmeme 上出现。[Google 博客](https://blog.google/innovation-and-ai/models-and-research/quantum-computing/magic-state-cultivation-quantum-computing/) ｜ [Techmeme](https://www.techmeme.com/261017/p19#a261017p19)
