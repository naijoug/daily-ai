## 新产品
1. **AgentValley: every Claude Code agent at a glance in your MacBook notch**: a free, open-source Mac app by Morse Chimwai that puts each Claude Code session on a card and each sub-agent on a row, with a tiny pixel character per agent; you see who's working, on which model, and who's waiting on you. It reads Claude Code's per-session status files rather than hooks, so permission prompts and "done" states show up in the notch even over a full-screen video. DMG builds are on GitHub. https://agentvalley.app [GitHub](https://github.com/morsechimwai/agent-valley) [Product Hunt](https://www.producthunt.com/products/agentvalley)
> [zh] **AgentValley：把每个 Claude Code agent 都放到 MacBook 刘海里一眼看清**：Morse Chimwai 做的免费开源 Mac 应用，每个 Claude Code 会话一张卡片、每个子 agent 一行，还给每个 agent 配一个像素小人；你能看到谁在干活、用的什么模型、谁在等你。它读的是 Claude Code 每个会话的状态文件而不是 hooks，所以即使全屏看视频，授权提示和「做完了」也会出现在刘海里。GitHub 上有 DMG 安装包。

Bring your own Claude Code/Codex plan, API keys or local models; client is free. Trending on GitHub today. https://cindy.app [GitHub](https://github.com/makecindy/cindy)

3. **Hallmark: a design skill that ends AI slop for Claude Code, Codex and OpenCode**: install with `npx skills add nutlope/hallmark -g`; it picks one of 48 material themes (or designs from scratch), asks for real photos and numbers instead of inventing them, lays out the page, then runs a linter that blocks floor issues (contrast, focus, reduced motion, invented facts, broken phone layout). Also supports `/hallmark redesign` and `/hallmark audit` on existing pages. https://www.usehallmark.com [GitHub](https://github.com/Nutlope/hallmark)
> [zh] **Hallmark：给 Claude Code、Codex 和 OpenCode 用的、专治 AI 审美垃圾的设计 skill**：一行 `npx skills add nutlope/hallmark -g` 安装；它从 48 套材质主题里选一套（或从零设计），会向你要真实照片和数字而不是瞎编，排好版后再跑一套 linter，把对比度、焦点、减弱动效、编造事实、手机布局崩坏等「底线」问题拦下来。还支持对已有页面做 `/hallmark redesign` 和 `/hallmark audit`。

1. **Node2Shell evolves to HTTP2Shell: the same Brotli RCE now spans many HTTP stacks**: Aikido's Oct 23 update says CVE-2026-111497 (CVSS 9.2) is no longer just Node/Python — patches are out for libbrotli, C++, Bun, Envoy and Istio, with more coming; Apache/Nginx do not decode Brotli by default. OpenAI says it found the bug in February and the root cause was fixed upstream then, but it wasn't treated as a security issue so consumers only now ship updates. Scanners still often miss the PyPI packages. If you can't upgrade, reject `br` at the edge and strip it from Accept-Encoding. HN discussion: https://news.ycombinator.com/item?id=50219177 https://www.aikido.dev/blog/python-packages-vulnerable-node2shell-brotli-cve-2026-111497
> [zh] **Node2Shell 演变成 HTTP2Shell：同一个 Brotli 远程代码执行漏洞已波及大量 HTTP 栈**：Aikido 10 月 23 日更新称 CVE-2026-111497（CVSS 9.2）不再只是 Node/Python——libbrotli、C++、Bun、Envoy、Istio 等已有补丁，还会有更多；Apache/Nginx 默认不解 Brotli。OpenAI 称 2 月就发现了该问题，上游当时修了根因，但没当安全漏洞处理，所以下游现在才陆续发版。扫描器仍常漏报 PyPI 包。暂时升不了的，可在边缘拒绝 `br`，并从 Accept-Encoding 里去掉它。

3. **InfoQ：React 19.3 新增 `browser()` API，让「仅客户端渲染」成为一等公民**：配合 `use(browser())`，组件可在服务端暂停、在 Suspense 边界留下 fallback，水合后再渲染，用来读 `localStorage`/`window`/时区等浏览器专属 API，不必再写 `typeof window !== 'undefined'` 或 mounted 标志。适用于任意 SSR 配置，不只绑在 Next.js 的 `dynamic(..., { ssr: false })` 上。https://www.infoq.cn/article/jNX6EAzqP34xRjqUMU1N
> [en] **InfoQ: React 19.3 adds a `browser()` API that makes client-only rendering first-class**: with `use(browser())`, a component can pause on the server, leave a Suspense fallback, then render after hydration for `localStorage`/`window`/timezone and similar browser-only APIs, without `typeof window !== 'undefined'` or mounted flags. It works with any SSR setup, not only Next.js `dynamic(..., { ssr: false })`.
