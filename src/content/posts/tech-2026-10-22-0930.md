## 新产品 / 开源
1. **DuckDB 2.0.0 LTS「Cinnamon Teal」**：这是 DuckDB 迄今最大的功能版本，距 1.5 有近 2 万次提交，支持到至少 2027 年 10 月。亮点包括打磨后的 Quack 协议和新的 CONNECT 语句（DuckDB 可以按客户端-服务器方式跑）、异步 I/O、一等公民的 VARIANT 类型、触发器和可扩展的 SQL 解析器。对写 agent 的人最有意思的是 CLI 的 agent 模式：检测到是 Claude Code、Codex、Cursor 这类 agent 在调用时，会改输出紧凑的 Markdown 表格、明确说明结果被截断、提前终止失控查询、错误以 JSON 返回，长查询还会先报预计开销；官方在 TPC-H 上测，模型要读的输出少了 59%，也可以用 `-agent`、`-no-agent` 手动切换。[DuckDB 博客](https://duckdb.org/2026/10/21/announcing-duckdb-200) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50181136)
2. **Opposable：在手机上本地跑的 2B computer-use 模型（Show HN）**：这是一个 Android 应用，通过无障碍服务读屏幕、在其他 App 里点击和输入；电脑上的 Claude、ChatGPT、Codex 可以远程驱动它，没连上时就用手机上的 GUI-Owl 1.5 2B（阿里 Mobile-Agent 团队基于 Qwen3-VL 微调，4 bit 量化跑在 llama.cpp 上）自己完成。在 Mac M2 CPU 上一步约 7.3 秒，其中一半花在视觉编码器上，换到 Galaxy S25 的 NPU，编码只要 236ms。设闹钟、发短信这类约 40 个常见任务直接走固定代码，不经过模型。[博客](https://getopposable.com/blog/computer-use-on-the-phone) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50180190)（有人问为什么不直接用 ADB）
3. **Omnara：开源、可自托管的托管 agent 平台（Show HN）**：定位是 Claude Managed Agents 和 OpenAI Agents API 的开源替代，用一套 API 在任意模型、任意机器上跑 agent，工具、密钥、权限和流式输出都内置，Apache 2.0 协议，后端是 Go，也有云服务版。不想把 agent 运行时绑在某一家厂商上的团队可以看看。[GitHub](https://github.com/omnara-ai/omnara) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50183892)
4. **graphify：把代码库变成可查询的知识图谱，给 coding agent 用**：今天 GitHub Trending 涨了 1,400 多星。在 Claude Code、Cursor、Codex、Gemini CLI 里输入 `/graphify`，它会用 tree-sitter 在本地解析代码 AST 建图（不调用 LLM，代码不出本机），文档、PDF、图片再用你的模型做一轮语义补充；每条边都标明是源码里明确写的（EXTRACTED）还是推断出来的（INFERRED），让 agent 查图而不是到处 grep。[GitHub](https://github.com/Graphify-Labs/graphify)
5. **Google 公开 Rust 风格指南**：内容是 Google 内部（含 Chrome）写 Rust 的约定，比如优先拆小 crate、不用 glob import、尽量避免 Rc 和 Arc、能借用就别深拷贝、API 里用 enum 代替 bool、newtype 和类型别名怎么选等。团队要定 Rust 规范、或者想给 agent 写编码规则时可以直接参考。[Google Style Guides](https://google.github.io/styleguide/rustguide.html) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50186010)

## 科技新闻
1. **LiteLLM 1.107.0 在 PyPI 上被投毒，装了就会偷凭据并留后门**：SafeDep 分析，这个版本的 7 个 wheel 都多装了三个文件，其中 `cook.pth` 会让主机上任何 Python 进程启动时都运行窃密脚本（哪怕根本没 import litellm），收集 SSH 密钥、云凭据、CI/CD 密钥、浏览器密码、LiteLLM 代理数据库里的模型 key，以及 Claude Code、Cursor、Codex 等 AI 工具的配置；`sitecustomize.py` 再起一个每小时联网拉代码执行的后门。GitHub 上的源码里没有这些东西，SafeDep 判断是 BerriAI 的私有发布流水线从被篡改的源码构建了这批 wheel。PyPI 已下架该版本，1.106.2 和两个 rc 是干净的。装过的机器应当按凭据全部泄露处理并轮换。[SafeDep](https://safedep.io/litellm-pypi-compromise-credential-stealer-backdoor/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50181114)（呼声最高的建议是让 uv、npm 默认对新版本设 24–48 小时冷却期）
2. **PHP 补丁已发布：8.5.12、8.4.27、8.3.36、8.2.35，赶紧升级**：PHP 基金会解释了两个漏洞的成因。CVE-2026-109618 是请求恰好在错误时刻触到 memory_limit，PHP 留下半初始化的内部数据并当作有效数据使用；在 Apache + mod_php 上，未认证请求在应用代码执行前就能触发，默认配置下已演示完整 RCE，PHP-FPM 上也通过应用代码路径确认了 RCE。CVE-2026-109619 是致命错误让内部状态指向上一个请求的内存，形成 use-after-free。这个 OOM 问题 2024 年外部审计时就露过苗头，但修法每种都有兼容性代价，才拖到现在。另一边，Elias Taylor 发文提醒，GitHub 上上千个「PoC」在原版 PHP 上都跑不起来，很多依赖本地文件包含这种前提，是 LLM 自信编出来的，别被吓到乱改，但该升级还是要升级。AWS 也发了各托管运行时的安全公告。[PHP 基金会](https://thephp.foundation/blog/2026/10/21/todays-php-security-release-and-how-were-strengthening-php-security/) ｜ [Elias Taylor](https://eliastaylor.com/noexploit/) ｜ [AWS 公告](https://aws.amazon.com/security/security-bulletins/2026-143-aws/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50182987) ｜ [HN：PHP 8.2.35](https://news.ycombinator.com/item?id=50180873)（评论在吐槽 Ubuntu 的包和官方 Docker 镜像晚了两个多小时才跟上，Debian 几乎是秒更）
3. **GitLab 紧急补丁：CVSS 10.0，未认证就能在自建服务器上执行代码，7.0 以来的版本全受影响**：CVE-2026-110264 是正则编译器里的整数溢出，攻击者构造特殊正则就能执行任意代码。修复版本是 19.5.1、19.4.3、19.3.6、19.2.9、19.1.9、19.0.10、18.11.13，GitLab.com 已经修好。官方还给了两条检测规则（Onigmo 原生 worker 崩溃、Org mode 渲染错误激增）用来排查是否已被利用。同一批还修了 OmniAuth 与 LDAP 自动关联导致的账号接管等 11 个问题。自建 GitLab 的今天就要升。[GitLab 公告](https://docs.gitlab.com/releases/patches/patch-release-gitlab-19-5-1-released/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50185869)
4. **Railway 披露：客户环境变量可能被读走，部分已被解密**：Railway 发现存放客户环境变量的系统有异常访问，攻击方可能拿到了加密的环境变量，其中一部分拿到了明文。官方认为这是最近一连串针对平台公司、意在拿到 AI 推理服务商 key 的攻击之一，已经通知上游推理厂商主动吊销 key。所有部署暂停，建议所有用户立即轮换 Railway 里的全部环境变量、API key 和私有镜像仓库凭据，并检查日志；之后又补发了排查 GCP、AWS 异常访问的指引。[Railway 博客](https://blog.railway.com/p/security-disclosure-wednesday-october-21st) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50188228)（评论把 PHP、eMudhra 证书、Railway 连在一起，担心以后天天都是这种日子）
5. **QPACK 放大攻击：一条连接就能把 HTTP/3 服务器的内存打爆**：FoxIO 测了 10 个 HTTP/3 实现，7 个有问题：QPACK 头部压缩缺少或太晚执行解码后头部大小的限制，一个很小的 HEADERS 帧能展开成几十万个头部对象。quic-go 0.57.0、Cloudflare quiche 0.29.3、lsquic 4.9.0、Wireshark 已修；Bun、hyperium 的 h3、aioquic/mitmproxy 截至 10/20 还没修，建议 Bun 先别对外开 HTTP/3、mitmproxy 用 `--set http3=false`、h3 设置 `max_field_section_size`。IIS、Envoy、ngtcp2/nghttp3 不受影响。[FoxIO](https://foxio.io/blog/header-accordions-qpack-amplification-attacks-against-http-3-servers) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50188612)
