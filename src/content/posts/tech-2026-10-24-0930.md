## 新产品
1. **Dessa: Block's full-duplex speech model trained only on human conversation audio**: a small lab at Block (ex-members of the Toronto startup Dessa, reporting to Jack Dorsey) trained it from scratch on speech alone, with no text and no pretrained models, so it listens and talks at the same time, backchannels, laughs mid-sentence and hears sarcasm or a sigh that speech-to-text pipelines throw away. Inference is faster than real time and runs locally on a MacBook Pro M4 Max or better; training used a single GB200 NVL72. It's waitlist-only for now, with early access for AI safety researchers. HN was split: some found the samples uncanny and say the intelligence feels "2024-level", others expect joint text+audio training to be the next step. https://block.xyz/dessa [HN](https://news.ycombinator.com/item?id=50213925)
> [zh] **Dessa：Block 只用人类对话音频训练的全双工语音模型**：Block 内部一个小实验室（成员来自多伦多创业公司 Dessa，直接向 Jack Dorsey 汇报）从零开始只用语音训练，不用文本、不用预训练模型，所以它能边听边说、适时附和、话说一半就笑出来，还能听出语音转文字流程会丢掉的讽刺和叹气。推理比实时更快，可在 MacBook Pro M4 Max 及以上本地运行；训练只用了一台 GB200 NVL72。目前只能排队等候，并向 AI 安全研究者开放早期访问。HN 上意见分化：有人觉得样例很诡异、智力像「2024 年水平」，也有人认为下一步就是文本加音频联合训练。
2. **Corgi: a terminal multiplexer built for running many coding agents**: like tmux it keeps agents and dev servers running in the background, but it also shows what each agent is doing and which one needs you (F1 jumps to the next unread), launches Claude Code, Codex, Pi or OpenCode with all your accounts, tracks where tokens went, replays every file an agent touched, and manages worktrees. `corgi --skill` teaches agents to drive it; image paste with ⌘V works even over SSH (Ghostty Nightly). Written in TypeScript on Bun, inspired by herdr; one early user calls it a good cmux replacement. https://corgi.computer [HN](https://news.ycombinator.com/item?id=50214373)
> [zh] **Corgi：为同时跑多个编程 agent 设计的终端复用器**：它像 tmux 一样让 agent 和开发服务器在后台持续运行，还会显示每个 agent 在干什么、哪个在等你（按 F1 跳到下一个未读），能用你的多个账号启动 Claude Code、Codex、Pi 或 OpenCode，统计 token 花在哪，回放 agent 改过的所有文件，并管理 worktree。`corgi --skill` 可以教 agent 自己操作它；⌘V 粘贴图片连 SSH 下都能用（需 Ghostty Nightly）。用 TypeScript 基于 Bun 编写，灵感来自 herdr；有早期用户说它是 cmux 的好替代。
3. **Monish: put your agents on the iPhone lock screen, with Approve/Deny before risky actions**: paste one line into Claude Code, Codex, Cursor, n8n or a cron job and the agent reads a short guide; long runs then appear as a Live Activity and in the Dynamic Island, you get one ping when work lands (failures can ring through quiet hours), and before it deploys, sends or spends money it asks, and you tap Approve or Deny on the notification. No account, no SDK, nothing installed on your computer; messages are deleted from the server after 48 hours. Free, launched on Product Hunt today by Marius Labs. https://monish.cc [Product Hunt](https://www.producthunt.com/products/monish)
> [zh] **Monish：把 agent 放到 iPhone 锁屏上，危险操作前先让你批准或拒绝**：在 Claude Code、Codex、Cursor、n8n 或定时任务里粘贴一行，agent 读完一份简短说明后，长任务会以实时活动的形式显示在锁屏和灵动岛上，完成时提醒你一次（失败可以在免打扰时段照样响铃），在部署、发送或花钱之前会先问你，直接在通知上点批准或拒绝。不用注册、不用 SDK、电脑上什么都不用装；消息 48 小时后从服务器删除。免费，Marius Labs 今天在 Product Hunt 发布。
4. **ThinkingCap for Gemma-4-26B-A4B: 39% less thinking on average, same accuracy**: BottleCap AI post-trained Google's sparse MoE (26B total, ~4B active) to reach answers with fewer reasoning tokens: across 12 benchmarks thinking drops 38.9% on average (up to 69.1%) for a 0.15pp accuracy cost, and looping falls from 3.6% to 0.8% of responses. It's a drop-in replacement with the same sampling settings on vLLM. HN users who tried earlier ThinkingCap Qwen models say they're a bit dumber and more censored than the originals, while others note shorter reasoning matters most for cost-bound jobs like PR review. https://bottlecapai.com/post/thinkingcap-gemma-4-26b/ [HN](https://news.ycombinator.com/item?id=50209907)
> [zh] **ThinkingCap 版 Gemma-4-26B-A4B：平均少想 39%，准确率不变**：BottleCap AI 对 Google 的稀疏 MoE 模型（总参数 26B、每个 token 约 4B 激活）做后训练，让它用更少的推理 token 得出答案：12 个基准上思考量平均降 38.9%（最多 69.1%），准确率只掉 0.15 个百分点，陷入循环的回答从 3.6% 降到 0.8%。采样设置不变，可在 vLLM 上直接替换。HN 上试过之前 ThinkingCap Qwen 模型的人说它比原版笨一点、审查也更严，也有人指出对 PR 审查这类按成本算的任务，推理更短才最重要。

## 科技新闻
1. **The Brotli RCE behind "Node2Shell" also hits Python, and scanners won't flag it**: the out-of-bounds write (CVE-2026-111497, CVSS 9.2) sits in Google's Brotli C decoder 1.0.3–1.2.0, so anything bundling it is exposed. OpenSourceMalware found the PyPI `Brotli` and `brotlicffi` packages ship the same decoder and were quietly fixed on Oct 22 with no advisory, while requests/urllib3, httpx and aiohttp decode `br` responses automatically when Brotli is installed. Run `pip install -U "Brotli>=1.2.1" "brotlicffi>=1.2.1.0"`, and move Node to 26.12.1, 24.22.1 or 22.23.4 (Node 20/23/25 get no fix; Bun is fixed in 1.4.4). HN notes the Rust `brotli` crate isn't a C binding and is unaffected; disabling `br` encoding is a stopgap. https://pwn.watch/i/nodejs-october-2026-security-releases [HN](https://news.ycombinator.com/item?id=50216791)
> [zh] **「Node2Shell」背后的 Brotli 远程代码执行漏洞也波及 Python，扫描器却不会报**：这个越界写漏洞（CVE-2026-111497，CVSS 9.2）出在 Google Brotli C 解码器 1.0.3–1.2.0 里，所有捆绑它的软件都受影响。OpenSourceMalware 发现 PyPI 上的 `Brotli` 和 `brotlicffi` 包用的是同一个解码器，10 月 22 日悄悄修复且没有发公告；而装了 Brotli 时，requests/urllib3、httpx、aiohttp 会自动解码 `br` 响应。执行 `pip install -U "Brotli>=1.2.1" "brotlicffi>=1.2.1.0"`，Node 升到 26.12.1、24.22.1 或 22.23.4（Node 20/23/25 不再修复；Bun 已在 1.4.4 修好）。HN 指出 Rust 的 `brotli` crate 不是 C 绑定，不受影响；临时可以关掉 `br` 编码。
2. **Pillow: one crafted image can run code through the FlashPix decoder (CVE-2026-112398)**: a heap overflow in Pillow's FPX JPEG-tile decoder triggers on a single `Image.open()`, and since Pillow detects FPX by its OLE2 content rather than the file extension, any service that opens or thumbnails untrusted uploads with the optional `olefile` package installed is exposed with no user interaction. The advisory ships a working PoC; Pillow 12.3.0 and earlier are affected, upgrade to 13.0.0 (GitHub rates it CVSS 4.0 9.2). https://pwn.watch/i/pillow-fpx-heap-overflow-cve-2026-112398
> [zh] **Pillow：一张特制图片就能通过 FlashPix 解码器执行代码（CVE-2026-112398）**：Pillow 的 FPX JPEG 分块解码器有堆溢出，一次 `Image.open()` 就能触发；而且 Pillow 按 OLE2 内容而不是扩展名识别 FPX，所以只要装了可选的 `olefile` 包，任何会打开或生成缩略图的不可信上传服务都会中招，无需用户交互。公告附带可用的 PoC；Pillow 12.3.0 及更早版本受影响，升级到 13.0.0（GitHub 评 CVSS 4.0 9.2 分）。

Google says advertisers don't see the content and sensitive categories are excluded. HN commenters read "might" as "will". https://www.theverge.com/tech/1017600/google-personal-intelligence-privacy-policy-ads-update [HN](https://news.ycombinator.com/item?id=50214218)

4. **Can a $150k Looker be replaced by a bucket of HTML files?**: a 3-person data platform team at a ~500-person company put Claude-generated HTML dashboards behind SSO on S3, then added a live query API that uses each viewer's Snowflake OAuth token, so Snowflake roles became the permission model for free. > [en] **InfoQ: Spotify doubled its monthly merged changes with AI-assisted development, and verification is struggling to keep up**: merged changes in August rose from about 8,100 to 17,000; complex changes go to Honk (a background coding agent running Claude via the Agent SDK in Kubernetes pods), with Fleetshift handling targeting, scheduling and progress tracking, and one backend Java migration took three days. > [en] **InfoQ: Xcode 27.2 introduces a JSON project format that cuts merge conflicts and is easier for agents to edit**: the new open-source xcode-project-format replaces the plist-based project.pbxproj (converted projects use project.xcproj), favoring readable names and paths over opaque IDs so diffs map one-to-one to actions in Xcode; Apple also released a Swift package to encode and decode it. Only the on-disk storage changes, not the underlying model; check that tools like fastlane, CocoaPods and Tuist support it before migrating.
