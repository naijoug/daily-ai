## 新产品 / 开源
1. **OpenCode 2.0**: a major refactor of the open-source coding agent. The server now stays resident by default as a background process, and the TUI, web version and desktop version all connect to the same process; the API was torn down and rewritten, agents can call their own API, e.g. automatically moving a session into a git worktree when starting a new task, and `@opencode/client` scripts can auto-discover the local server. [Release notes](https://anoma.ly/notes/opencode-2-0/) ｜ [HN discussion](https://news.ycombinator.com/item?id=50094994) (some like that it's one of the few open-source agents usable outside a TUI; others grumble the install script is absurdly slow because of progress-bar rendering, and another warns that after the upgrade tool calls all go through the background process, so sandboxes that used to wrap around the TUI will silently stop working)
> [zh] **OpenCode 2.0**：开源编程 Agent 的大版本重构。服务端现在默认作为一个后台进程常驻，TUI、网页版和桌面版都连同一个进程；API 推倒重写，Agent 还能调用自己的 API，比如开新任务时自动把会话挪进 git worktree，`@opencode/client` 脚本也能自动发现本地服务。[发布说明](https://anoma.ly/notes/opencode-2-0/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50094994)（有人喜欢它是少数能脱离 TUI 用的开源 Agent；也有人吐槽安装脚本因进度条渲染慢得离谱，还有人提醒升级后工具调用都走后台进程，原来包在 TUI 外面的沙箱会悄悄失效）
2. **Petal**: a free open-source pair-programming tool from the original CoScreen team, with low-latency multi-window sharing and remote control, where each shared window is a draggable native window on the other person's desktop; currently supports macOS and Windows, with Linux in the works. [Website](https://petal.live/) ｜ [GitHub](https://github.com/kiruna-labs/petal) ｜ [Show HN](https://news.ycombinator.com/item?id=50092470) (a Screenhero co-founder came by to congratulate, and commenters compare it with Tuple and ask how LiveKit's latency is tuned)
> [zh] **Petal**：CoScreen 原班人马做的免费开源结对编程工具，低延迟多窗口共享和远程控制，每个共享窗口在对方桌面上都是一个能拖动的原生窗口；目前支持 macOS 和 Windows，Linux 在做。[官网](https://petal.live/) ｜ [GitHub](https://github.com/kiruna-labs/petal) ｜ [Show HN](https://news.ycombinator.com/item?id=50092470)（Screenhero 联合创始人亲自来道贺，评论里也有人拿它和 Tuple 比，并问 LiveKit 的延迟调得怎么样）
3. **Graphicle**: a code-graph plus memory tool written in Rust that gives MCP clients like Claude Code, Codex and Cursor context with file and line references, running fully locally with no API key and no telemetry. [GitHub](https://github.com/graphicle-ai/graphicle) ｜ [Show HN](https://news.ycombinator.com/item?id=50088713) (one says in his evals such memory systems did worse than just giving ripgrep; another thinks binding memory to specific functions and invalidating it when the code changes is the real highlight)
> [zh] **Graphicle**：用 Rust 写的代码图谱加记忆工具，给 Claude Code、Codex、Cursor 等 MCP 客户端提供带文件和行号引用的上下文，全本地运行，不需要 API key，也没有遥测。[GitHub](https://github.com/graphicle-ai/graphicle) ｜ [Show HN](https://news.ycombinator.com/item?id=50088713)（有人说自己的评测里这类记忆系统还不如直接给 ripgrep；也有人认为把记忆绑定到具体函数上、代码改了就让记忆失效，才是它真正的亮点）
4. **neckbeard**: a coding-agent plugin aimed at agents going wild when writing infrastructure. Humans maintain a set of CI-tested OpenTofu modules; after reading the repo and asking questions the code can't answer, the agent maps the application onto these modules and attaches a monthly bill estimate. [GitHub](https://github.com/bealesh/neckbeard) ｜ [HN discussion](https://news.ycombinator.com/item?id=50091794) (someone questions whether just having the agent write OpenTofu plus Ansible is enough, and another says a $25 Hetzner box is plenty)
> [zh] **neckbeard**：一个编程 Agent 插件，专门对付 Agent 写基础设施时胡来。由人维护一套经过 CI 测试的 OpenTofu 模块，Agent 读完仓库、问清代码回答不了的问题后，把应用映射到这些模块上，还附上每月账单估算。[GitHub](https://github.com/bealesh/neckbeard) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50091794)（有人质疑直接让 Agent 写 OpenTofu 加 Ansible 就行，也有人说一台 25 美元的 Hetzner 足够了）
5. **iFixAi** (GitHub Trending, up 2,100+ stars today): a tool for independently auditing AI agents that either a human or the agent itself can run, claiming to answer "is this agent doing what it should?" within two minutes, with a Chinese README. [GitHub](https://github.com/ifixai-ai/iFixAi)
> [zh] **iFixAi**（GitHub Trending，今天涨了 2100 多星）：独立审计 AI Agent 的工具，人或 Agent 自己都能跑，号称两分钟内回答"这个 Agent 有没有在做它该做的事"，有中文 README。

## 科技新闻
1. **Linus Torvalds sends his first LLM-assisted patches**: 10 patches put folio data reads inside an RCU-protected section so the fast path no longer takes a reference count, an order of magnitude faster in a read()-heavy benchmark; but review has already found a race condition, so it needs another revision. [LWN](https://lwn.net/Articles/1100449/) ｜ [HN discussion](https://news.ycombinator.com/item?id=50090842) (someone is surprised he used closed-source Claude rather than an open model, others use it to discuss AI assistance on critical infrastructure, and some find LLM-written commit messages too wordy)
> [zh] **Linus Torvalds 发出第一组 LLM 辅助的补丁**：10 个补丁把 folio 的数据读取也放进 RCU 保护区，快路径不用再拿引用计数，在大量 `read()` 的基准测试里快了一个数量级；不过评审已经发现一个竞态条件，还要再改。[LWN](https://lwn.net/Articles/1100449/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50090842)（评论里有人惊讶他用的是闭源的 Claude 而不是开源模型，有人借此讨论关键基础设施用 AI 辅助的问题，也有人嫌 LLM 写的 commit message 太啰嗦）
