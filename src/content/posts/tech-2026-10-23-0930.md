## 新产品
1. **MiniMax M3.1 Flash：开源权重，428B 总参数、23B 激活**：MiniMax 今天开源 M3.1 Flash，相比 M3 全面提升。推理效率上做了三件事：前三个全注意力层也换成稀疏注意力，全模型都是稀疏注意力；量化感知训练把路由 MoE 专家迁到 W4A4（共享专家除外），KV 从 Q8KV8 降到 Q8KV4；再按算卡功耗精细调度，让算力保持在高位。官方说它 10/19 上线后 72 小时处理了超过 100 万亿 token；首日就有昇腾、平头哥、昆仑芯、英伟达、AMD 等芯片，以及 Together、Fireworks、Modal 等云平台接入，vLLM、SGLang 也同步支持。想找一个能自己部署的强开源 agent/编码模型，可以把它列进候选。[魔搭](https://modelscope.cn/models/MiniMax/MiniMax-M3.1-Flash) ｜ [Hugging Face](https://huggingface.co/MiniMaxAI/MiniMax-M3.1-Flash) ｜ [IT之家](https://www.ithome.com/1/016/800.htm)
2. **EmbeddingGemma 2：Google 开源 740M 多模态嵌入模型**：把文本（含代码）、图片、视频、音频映射到同一个 768 维向量空间，由 270M 文本主干加可按需加载的视觉（170M）、音频（300M）编码器组成，只用文本时可以不加载另外两块。支持 100 多种语言，代码任务比上一代提升约 14%，上下文 8K，向量可截断到 128/256/512 维（存储最多省 6 倍），用指令前缀区分检索、分类、聚类等任务。Apache 2.0 协议，面向手机和笔记本本地跑，做端侧 RAG 或多模态搜索很合适。[Gemma 文档](https://ai.google.dev/gemma/docs/embeddinggemma) ｜ [Google 博客](https://blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2) ｜ [Hugging Face](https://huggingface.co/google/embeddinggemma-2)
3. **Loom Record for agents：录一段屏幕，直接交给 AI 去做**：Loom 新版 Mac 应用加了「为 agent 录制」，同时录下视频、声音和屏幕上的操作，自动转成任何 AI 工具都能执行的 prompt，省得你打字描述屏幕上发生了什么；Chrome 扩展也能用，免费。新版 Mac 应用还支持精确区域录制，默认 4K。今天在 Product Hunt 上线。给 agent 复现 bug、演示一段操作流程时会很顺手。[Loom](https://www.loom.com/) ｜ [Product Hunt](https://www.producthunt.com/products/loom)
4. **Hy-Memory-30B-A3B：腾讯混元专门「写记忆」的小模型**：约 3B 激活参数，只负责外部记忆框架里的写入环节，也就是决定记什么、记多细、新信息来了怎么更新记忆库，可以直接替换 Mem0、MemOS 和 Hy-Memory 里原本的通用大模型。训练分两步：先做 on-policy 蒸馏，再用按记忆块打分的强化学习；评测时只换写入模型，检索、回答模型和裁判都固定，在训练时没见过的 EverMemOS 上也能迁移。Apache 2.0。给 agent 做长期记忆、又嫌每次写入都调大模型太贵的，可以试试。[Hugging Face](https://huggingface.co/tencent/Hy-Memory-30B-A3B)
5. **MOSS-Image：复旦 OpenMOSS 开源文生图模型，中文排字表现好**：分 Base 和 SFT 两个版本，Apache 2.0，用 diffusers 自定义 pipeline 加载，也提供 ComfyUI 节点。除了自然语言 prompt，还支持标签序列和 JSON 布局来控制文字位置和物体摆放，官方示例就是在冰箱便利贴上手写三行中文。目前在 Hugging Face 趋势榜靠前。[GitHub](https://github.com/OpenMOSS/MOSS-Image) ｜ [Hugging Face](https://huggingface.co/OpenMOSS-Team/MOSS-Image-SFT)

## 科技新闻
1. **GitHub 用 AI 把 Copilot 运行时从 TypeScript 整体迁到 Rust**：Copilot CLI、Copilot 应用和 SDK 背后的运行时用了约 14.5 周、128 个 PR 完成迁移，替换 80 多万行代码，绝大部分由 agent 生成，靠编译、测试和人工评审抓回归。做法是逐个组件替换，中间用临时的 N-API 互操作层衔接，迁移期间照常发了 135 个版本；4478 次 cargo check 里 87.1% 一次通过。结果是启动、建会话加一轮交互从 5.25 秒降到 292 毫秒，还省掉每个客户端约 100MB 的 V8 内存，可以通过 C ABI 直接嵌进宿主应用。评论区的关注点是取消、重试、背压这类行为光靠编译验证不了。想用 AI 做大规模重写的团队值得细读。[InfoQ 中文](https://www.infoq.cn/article/zGqDWHF8tHDtlYcImAJS) ｜ [InfoQ 英文原文](https://www.infoq.com/news/2026/10/github-copilot-rust-migration/)
2. **Quad9 将于 11 月 24 日退出法国**：法国法院支持 beIN 体育，要求 Quad9 对法国用户屏蔽一批涉嫌盗播的域名，罚金从每天 58 万欧元降到 1000 欧元，但 Quad9 认为递归 DNS 应是中立服务，拒绝篡改解析结果，干脆停止为法国用户服务。这是 HN 今天最热的帖子（近 1000 分），讨论集中在用 DNS 层执法到底有没有用、以及欧洲其他国家会不会跟进。[Quad9 博客](https://quad9.net/news/blog/au-revoir-france/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50195959)

4. **Canva 发布首个自研生图模型 Canva Craft**：先把 prompt 解析成一份规划（元素的空间关系、相对大小、视觉层级和要写的文字），再生成最高 2K、30 种比例的图片，所以文字更清楚，也能只改局部。训练数据不是照片，而是 Canva 模板库里人工设计的海报、幻灯片、信息图、菜单等，生成结果还能用 Canva Magic 转成可编辑的分层设计。所有用户都能在 Dream Lab 里用，之后开放 API，并计划通过 Canva 的 MCP 在 ChatGPT、Gemini 里调用；更便宜的 Craft-fast 和 Craft-ultrafast 版本也在做。[TechCrunch](https://techcrunch.com/2026/10/22/canva-releases-its-first-image-generation-model/) ｜ [The Verge](https://www.theverge.com/ai-artificial-intelligence/1017151/canva-craft-in-house-ai-model)
5. **pwn.watch：一页看清「现在什么在被打」和补丁出没出**：@thekitze 做的安全事件追踪页，列出过去 12 个月 239 起重大事件，按严重级别和「已修补 / 部分修补 / 未修补」筛选，当前有 40 起活跃事件，比如 Arista VeloCloud Orchestrator 零日、FortiMail 未认证写文件零日、eMudhra CA 私钥泄露。提供 RSS、JSON 和 llms.txt，还有一键「复制给 AI 的简报」，适合接进自己的告警或 agent。HN 342 分。[pwn.watch](https://pwn.watch/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50195543)

## 中文社区
1. **V2EX：Codex 桌面版崩溃转储会悄悄吃掉几十上百 GB**：macOS 版 Codex 的崩溃上报卡住时，Crashpad 会不停往本地写转储文件且没有任何提示，官方 issue 6 月就开了至今未修，有人一天涨 4.9GB，评论里有人删了 80 多 GB。自查命令：`du -sh ~/Library/Application\ Support/Codex/Crashpad ~/Library/Application\ Support/com.openai.codex/web/Crashpad`；清理时先退出 Codex，再删掉其中 pending、completed、new、attachments 目录里的内容（保留 Crashpad 文件夹和 settings.dat）。其他 Electron 应用用的是同一套机制，也可以顺便查。[V2EX](https://www.v2ex.com/t/1250986) ｜ [GitHub issue](https://github.com/openai/codex/issues/25921)
2. **LinuxDo：基于 Hindsight 的企业级记忆系统怎么分库**：楼主总结了一次架构讨论，结论是不要「一个 agent 一个记忆库」，而是记忆跟人走：每人一个个人库，编码场景按「用户 + 项目」再建一个库，团队库要人工审核后才发布。分工原则是用库做强隔离（用户、项目、权限），用标签做库内的范围过滤，用元数据记录来源（哪个产品、哪次会话、哪个 commit），并提醒后台的自动整合也必须守同样的边界，光靠召回时按标签过滤不够安全。给多 agent 产品设计记忆的可以参考。[LinuxDo](https://linux.do/t/topic/3061870)
3. **V2EX 分享创造：嫌 IDEA 太吃内存，自己写了个开源平替 OpenIDEA**：快捷键、工具窗口、双击 Shift 搜索都照着 IDEA 做，已经能补全、跳转、查引用、跑测试、断点调试，Git、终端、数据库、HTTP 请求也都集成了，靠配置文件支持 60 多种语言。评论区有人说「JetBrains 没做成的 Fleet，在 AI 时代能成了」，也有人更想要单独的 IDEA Git 工具。[V2EX](https://www.v2ex.com/t/1251116) ｜ [GitHub](https://github.com/l0ng-ai/openidea)
