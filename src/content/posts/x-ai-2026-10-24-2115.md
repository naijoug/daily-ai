2. **AWS open-sources Agent Toolkit for coding agents**: `aws/agent-toolkit-for-aws` packages MCP access to 300+ AWS APIs, sandboxed Python execution, live docs search, and curated skills (service choice, CDK/CloudFormation, serverless, containers, Bedrock/AgentCore, data/ETL, DevSecOps) as plugins for Claude Code, Codex, Cursor, Kiro and others. Install with `aws configure agent-toolkit` (AWS CLI 2.35.0+) or `npx skills add aws/agent-toolkit-for-aws/skills`; the repo was trending on GitHub in this window. Still need least-privilege IAM, spend limits and an audit trail before production. https://github.com/aws/agent-toolkit-for-aws | https://x.com/ainotesus/status/2113966433596031035
> [zh] **AWS 开源面向编程 Agent 的 Agent Toolkit**：`aws/agent-toolkit-for-aws` 把 300 多个 AWS API 的 MCP 访问、沙箱 Python 执行、实时文档搜索，以及服务选型、CDK/CloudFormation、无服务、容器、Bedrock/AgentCore、数据/ETL、DevSecOps 等精选 skills 打成插件，适配 Claude Code、Codex、Cursor、Kiro 等。可用 `aws configure agent-toolkit`（需 AWS CLI 2.35.0+）或 `npx skills add aws/agent-toolkit-for-aws/skills` 安装；本窗口内在 GitHub 上了趋势。上生产前仍要自己管好最小权限 IAM、花费上限和审计。
3. **Agentic SDLC 还不等于软件工厂：工程团队须自建并拥有有边界的 L4 系统**：Qodo 创始人 @itamar_mar 认为，各阶段都挂上 Agent 只是迈向软件工厂的一步，真正难的是把 Agent 周围的系统工程做好。L4 目标是有边界的自动化（能定义完成标准、失败回退和所有权），工厂系统必须由工程团队自己构建并拥有，而不是外包给模型供应商的黑盒编排。shao__meng 做了中文整理。https://x.com/shao__meng/status/2113923043936612792 | https://x.com/itamar_mar/status/2113255396299128887
> [en] **Agentic SDLC is not yet a software factory: engineering teams must build and own a bounded L4 system**: Qodo founder @itamar_mar argues that agents at every SDLC stage are only a step toward a factory; the harder work is engineering the system around them. L4 means bounded automation with clear done criteria, failure fallbacks and ownership, and that factory system has to be built and owned by the engineering team, not outsourced as a black-box orchestrator from a model vendor. shao__meng wrote the Chinese summary.

## 有趣用法和干货
1. **Claude 工程负责人 Felix：别再用 2024 年的方式用 Claude；少当传话筒，给全量数据与工具，用对抗评审，少堆角色 Agent**：Anthropic 的 Felix Rieseberg 在访谈里重申他文章《How to be more ambitious》的观点——几乎不再手写代码，核心不是造更多角色 Agent，而是把崩溃数据、业务工具和电脑交给模型，用对抗评审与外部证据约束输出。实用招：同一产出开多条线程专攻「证明你错了」，再开一条做 judge；多数任务不设人设，给全景业务视图加文档清楚的工具，比给每个 agent 切一小片数据更有效；Skills 半衰期短，有时删掉反而更好；最不信的是同一会话自评。文章按速度/高度/深度/广度四级示范怎么把「做 QBR PPT」抬成「设计比季度 deck 更早发现问题的机制」。https://x.com/shao__meng/status/2113970197161988276 ｜ https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/ ｜ https://www.youtube.com/watch?v=D-SVFneJ_Nk
> [en] **Claude engineering lead Felix: stop using Claude the 2024 way; stop being a messenger, give full data and tools, use adversarial review, pile on fewer role-play agents**: Anthropic's Felix Rieseberg restates his essay *How to be more ambitious* in an interview — he barely writes code himself; the point is not more persona agents, but handing crash data, business tools and a computer to the model, then constraining output with adversarial review and external evidence. Practical move: spin threads whose job is "prove this wrong," plus a judge thread; skip personas on most tasks; give a full business view plus well-documented tools rather than slicing data per agent; skills go stale fast and deleting them sometimes helps; he trusts same-session self-grading least. The essay walks Speed / Altitude / Depth / Range, turning "make a QBR deck" into "design a system that catches problems earlier than a quarterly deck."
2. **Vox：AGENTS.md 里最值钱的一行——让 agent 每条回复都以你的名字开头**：写在第一行：`Start every reply with "[your name],". No exceptions.` 一旦它不再叫你的名字，就说明规则开始脱落，立刻发交接提示：写一份给新会话的 handoff（目标、已完成、决策与理由、未解决问题、下一步，保留路径和命令），粘到新会话继续。比等它悄悄跑偏再发现更早。https://x.com/Voxyz_ai/status/2113978828619927815
> [en] **Vox: the most valuable line in AGENTS.md — make the agent start every reply with your name**: put on line one: `Start every reply with "[your name],". No exceptions.` The day it stops using your name, rules are slipping; send a handoff prompt (goal, done, decisions and why, open problems, exact next step, keep paths and commands) and paste that into a fresh session. You catch drift earlier than waiting for quiet failure.
3. **Gemini API CLI（`gemini-api`）：给 Claude Code / Codex 一个调用全部 Gemini 能力的单文件 Go 命令行**：Google 10 月 19 日放出的实验预览，一个零依赖二进制覆盖文生图/视频/音乐/配音、文件分析、转写，以及后台 Managed Agents；`--help` / `--usage` / `--schema` / `--dry-run` 自描述，媒体写到磁盘只回路径，不把 base64 灌进上下文。装好、配好 `GEMINI_API_KEY` 后，多数情况只需在 AGENTS.md 里提一句「需要媒体或 Gemini 时用 gemini-api」，agent 会自己读帮助。https://github.com/google-gemini/gemini-api-cli | https://aistudio.google.com/learn/introducing-the-gemini-api-cli | https://x.com/heynoxyz/status/2113963321284247619
> [en] **Gemini API CLI (`gemini-api`): one Go binary that gives Claude Code / Codex every Gemini capability**: Google's Oct 19 experimental preview — a zero-dependency CLI for image/video/music/voiceover generation, file analysis, transcription, and background Managed Agents; `--help` / `--usage` / `--schema` / `--dry-run` are self-describing, and media lands on disk as a path so base64 never floods the context. After install and `GEMINI_API_KEY`, often all you need in AGENTS.md is "use gemini-api for media or Gemini," and the agent reads the help itself.
