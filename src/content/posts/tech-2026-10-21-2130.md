## 新产品 / 开源
1. **tsrs：Cloudflare 和 VoidZero 把 TypeScript 编译器移植到 Rust**：这是在 TypeScript 团队配合下做的忠实移植，不是 fork，语言设计仍由官方决定，项目放在 Oxc 工具链里孵化。官方说在类型检查 worker 数相同的情况下，它比 TS 7.0 快最多 8 倍、内存少约 70%，还有一部分优化已经回馈给了 TS 7.1 beta。选 Rust 而不是 Go 的主要原因是编译到 WebAssembly 时不用带垃圾回收器，方便在浏览器和 Workers 里跑完整的开发环境。文中也直说，现在前沿模型几天内就能基本独立完成这种大规模移植。现在可以 `npx tsrs` 试用实验版。[Cloudflare 博客](https://blog.cloudflare.com/typescript-rust-port/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50165953)（422 分。有人数出现在已经有 tsrs、tsgo-rs、`bun check` 三个移植版本；用大型代码库的人很期待提速，但对作者「一行代码都没写」的说法不太舒服）
2. **Mercury 3：扩散式 LLM 做到了 GPT-6 Luna 这一档**：Inception Labs 说，Mercury 3 在 NVIDIA GPU 上每秒能出 1,068 个 token，比同档的 GPT-6 Luna、Claude Haiku 5.5 快 4–8 倍，质量持平或更好。上下文 1M，价格是每百万 token 输入 0.2 美元、输出 0.7 美元，上线期间打五折。参数量是 Mercury 1 的 40 多倍，官方的结论是扩散模型也符合 scaling law。合作方在 Mind2Web 的 50 个真实网页导航任务上测过，完成率 50%，比 GPT-6.1 Sol 高。浏览器 agent 每一步都要等模型返回，这种对延迟敏感的场景值得试试。[Inception 博客](https://www.inceptionlabs.ai/blog/introducing-mercury-3) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50155245)（联合创始人亲自来答疑；有人可惜它不是开源权重，也有人问 token 不按顺序生成，还怎么看懂模型在「想」什么）
3. **Mistral Voxtral 3：语音识别、语音合成和语音 agent SDK 一起发布**：Voxtral Small Transcribe 3 支持 50 多种语言，能区分说话人，也能用给定的关键词提高术语识别率，官方说效果超过 Whisper、Scribe v2 和 Gemini 3.5 Transcribe。4B 的 Mini 版每分钟 0.0035 美元，实时版延迟不到 500ms，能自己判断用户什么时候说完。TTS 支持 35 种以上语言，每百万字符 13 美元。新的 SDK 把听、推理、调用工具、说话放进同一条实时流水线。可以用欧盟托管的 API，也能部署在自己的服务器上。[Mistral](https://mistral.ai/news/voxtral-3/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50168396)（724 分。最多的意见是这次是闭源模型，想在本地跑语音的人很失望）
4. **cloudflare/security-audit-skill：让 coding agent 按流程做安全审计**：今天 GitHub Trending 上涨了近 2,000 星，Cloudflare 内部的漏洞挖掘系统就是从这个 skill 发展出来的。审计分六步：先侦察，画出架构、信任边界，建一份覆盖台账；再按台账派互相隔离的 agent 去找问题；每个可疑点交给新开的 agent，专门尝试推翻它；结果按「确认 / 待验证 / 驳回」写成带 schema 校验的 JSON；最后由另一批 agent 回到源码核对，再生成报告。附带的攻击类别覆盖 LLM 提示注入、供应链、云配置等。对这几天要排查 PHP 和证书问题的团队来说，正好可以参考。[GitHub](https://github.com/cloudflare/security-audit-skill)
5. **Laminar flow-1：用强化学习训练、专门从 agent 轨迹里找错的模型（Launch HN）**：作者的观点是，agent 的失败往往是隐性的，比如点错按钮、引错文档，每次调用都显示成功，所以只看最终输出是查不出来的。flow-1 把一条轨迹当成代码仓库、每个 span 当成一个文件，像 coding agent 一样边 grep 边读。在他们自己的 523 条难轨迹上，检测 F1 是 0.835，略高于 GPT-6-sol（0.816），低于 Claude Opus 5（0.890），但每美元能分析的轨迹数是 Sol 的 23 倍，每条约 0.001 美元，所以线上轨迹可以全部检查、不用抽样。[博客](https://laminar.sh/blog/flow-1) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50154029)（有评论指出更常见的失败是工具正常返回了，但结果本身不可信，比如缓存数据过期，或者网页里藏着注入指令）

## 科技新闻
1. **PHP 两个 CVSS 9.2 的严重漏洞，补丁预计北京时间今晚 22:00 发布**：PHP 官方提前预告了 CVE-2026-109618 和 -109619，安全公司 watchTowr 说这是远程代码执行漏洞，PHP 5 以后的版本都受影响。欧盟 CERT 和英国 NCSC 建议，没法马上打补丁的话，先把服务隔离或者下线。GrapheneOS 已经关了论坛，Cloudflare 说已经看到早期攻击，正在临时更新防火墙规则。Wordfence 提醒，WordPress 站点没法靠自动更新修复，要找负责 PHP 的人手动升级。网上流传的临时缓解办法是在 php.ini 里设 `session.upload_progress.enabled = Off`。HN 上被当成 PoC 转发的一篇分析，作者后来自己更正为「不能执行代码，只是中危的内存安全问题」，所以在官方公布细节之前，传言不要全信。[PHP 官方公告](https://www.php.net/archive/2026.php) ｜ [The Verge](https://www.theverge.com/tech/1015257/php-vulnerability-patch-website-security-wordpress) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50172041)（1,279 分。有人说如果传言属实，可能比 Log4Shell 还严重；荷兰 NCSC 的官网因为用 PHP 也临时下线了，见 [HN](https://news.ycombinator.com/item?id=50179828)）
2. **eMudhra 的 8 个中间 CA 私钥只有一个字节**：印度 CA eMudhra 有 6 个 TLS 签发 CA 和 2 个代码签名 CA，它们的 P-384 私钥前面 47 个字节全是 0，实际值只有 4、56、115 这样的一位数到三位数。Scott Helme 从公开证书出发，在笔记本上不到 1 秒就全部算了出来。这些 CA 还被 Sectigo 的 AAA 根交叉签名过，所以理论上能为任何网站签出受信任的证书。Chrome 和 Firefox 在 10/17 当天就通过 CRLSet、OneCRL 拦截了，Mozilla 还要移除 eMudhra 的根证书。Go 的维护者 Filippo Valsorda 对 Ars 说，这次清理比 Heartbleed 还大，麻烦的是那些自带根证书的语言运行时、容器和 IoT 设备。[Scott Helme](https://scotthelme.co.uk/eight-bits-of-trust-emudhras-ca-keys-cracked-in-milliseconds/) ｜ [Ars Technica](https://arstechnica.com/security/2026/10/the-internet-goes-on-high-alert-after-discovery-of-8-compromised-tls-certs/) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50166579)（1,065 分。评论里列了要升级的版本：Go 1.27.3 / 1.26.10、rustls-webpki 0.103.16、Python certifi 2026.10.19、Electron 44.9.1 等；Mozilla 的人说 Firefox 用户几小时内就自动得到了保护）
3. **WhatsApp 帮助页里藏着给 AI 看的指令，「不要建议用户找监管机构」**：Redact 读完了 WhatsApp 帮助中心链接的 545 个页面，发现 102 段用户看不见、只给客服 AI 读的文字。其中两段和 WhatsApp 公开的隐私政策相矛盾：删不了账号时，不要建议用户联系数据保护机构；用户一提到律师或诉讼，就不要引用 GDPR、CCPA，即使是用户自己先提的也一样。WIRED 联系 Meta 之后，这些文字被删掉了，官方说是「bug」。这件事提醒做 RAG 客服的团队，写在知识库里的东西都会被人挖出来对照。[Redact](https://redact.dev/blog/whatsapp-help-pages-hidden-ai-instructions) ｜ [HN 讨论](https://news.ycombinator.com/item?id=50159341)（732 分。有律师认为客服机器人不该给法律建议，这说得过去；但更多人觉得「不要推荐监管机构」怎么也不像 bug）
4. **AI 产品和数据库厂商接连出安全事故：Meta Muse 分享链接泄密，PingCAP 被拖库**：Muse 的分享链接把标识放在子域名里，安全公司 Claroc 用一次被动 DNS 查询就列出了 6,800 个链接，随手打开几百个，就看到了猎头对接前沿实验室的笔记、贷款申请、全年员工休假表等内容。Meta 已经暂停了分享功能。PingCAP 披露，9/9 到 10/7 之间有人用偷来的服务账号凭据访问了内部系统，拷走了 TiDB Cloud 的用户名和邮箱、SQL 编辑器里的内容、合同和计费数据，还有源码；官方说没有发现客户集群里的数据受影响。HN 评论引用攻击方的说法，他们还用仓库里提交的 GCP、Azure 凭据给控制面数据库搭了一个月的复制同步。[Ars Technica（Muse）](https://arstechnica.com/security/2026/10/meta-muse-exposes-users-personal-and-business-secrets-when-they-share-conversations/) ｜ [PingCAP 安全公告](https://www.pingcap.com/trust-hub/security/security-update-october-2026/) ｜ [HN（Muse）](https://news.ycombinator.com/item?id=50174687) ｜ [HN（PingCAP）](https://news.ycombinator.com/item?id=50173716)
