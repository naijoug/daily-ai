## AI 热点
1. **微软研究院：人类指挥 AI agent 探索 100 多条思路，证明 31 年悬而未决的 KLS 猜想**：Kannan–Lovász–Simonovits 猜想（1995 年提出）问的是高维对数凹分布里「最好的平面切割」是否总和「最好的任意形状切割」只差一个与维数无关的常数，它决定了高维随机游走采样能有多快。微软研究院的 Xinzhi Zhang 与 Zhao Song 给出了常数界；按微软博客的说法，AI agent 在研究者指挥下探索了 100 多条候选路线、做推导、帮写稿和内部检查，研究者负责筛选、剪枝和最终论证。Bizeul、Klartag、Lehec 已在 arXiv 发了基于这一判据的独立证明，也有人做了 Lean 形式化。这是「AI 当研究助手、人类掌舵」的又一个硬核案例。https://www.microsoft.com/en-us/research/blog/solving-a-31-year-old-grand-challenge-in-mathematics-the-kls-conjecture/ ｜ https://arxiv.org/abs/2610.05474 ｜ https://x.com/rohanpaul_ai/status/2113151168176443568
2. **讯飞发布端云一体星火 X2.6，并开源端侧 4B 模型**：旗舰 X2.6 是 293B 总参数、30B 激活的 MoE，上下文扩到 1M，讯飞称基于全国产算力训练，主打代码和智能体能力；API 限时 6 折，输入 0.9 元、输出 3.6 元每百万 token。端侧 Spark-X2.6-4B 已上 Hugging Face、ModelScope 和 Ollama（`ollama run SparkLLM/Spark-X2.6-4B`），新增三档推理模式；发布会演示了端侧本地做合同脱敏、云端再审核的分工。想在本地跑小模型 agent 的可以试试。https://www.ithome.com/1/016/403.htm ｜ https://huggingface.co/XHToken ｜ https://x.com/logang2008/status/2113178310658375960
3. **蚂蚁 Ling-3.1-flash-1019：Artificial Analysis 智能指数从 41 升到 44**：主要进步在 agent 任务，AA-Briefcase 从约 1400 升到 1524 Elo，AutomationBench-AA 从 62% 升到 68%；官方说 API 和开源权重即将放出。国产开源 MoE 在办公自动化类 agent 评测上继续追近。https://x.com/AntLingAGI/status/2113226531522891851
4. **Amp 支持自托管 orb（云端 agent 运行环境），个人和团队免费**：在自己的基础设施里运行 `amp orb provider ./dispatch.sh`，Amp 把创建、暂停、删除 orb 的请求转给你写的调度脚本，官方给了 Docker、E2B、K8s（Helm）、Apple container、Modal、Vercel、Daytona、exe.dev 的示例；要求机器启动快、能休眠恢复、能缩到零。主要面向代码不能出内网或需要特殊硬件的企业，企业版 10 月 29 日起按标准 orb 价格计费。想把云端编码 agent 放进自家网络的团队值得看看这套接口设计。https://ampcode.com/news/self-hosted-orbs ｜ https://x.com/thorstenball/status/2113140757410521159
5. **Breken 发布：在模拟的生产环境里替用户先把软件「跑坏」**：它在自己的机器上重建接近生产的环境，把数据和用户活动加速最多 4000 倍，再注入断连等故障，找到问题后还会尝试修复；X 新闻摘要提到它在 235 个开源项目真实 bug 上抓到 32%，而顶级模型直接找只有 16% 以下（这是公司自报数据）。原帖 117 万浏览、1700 多收藏，是今天讨论最多的开发工具发布之一。https://x.com/brekenai/status/2112936781087973732 ｜ https://breken.ai

## 有趣用法和干货
1. **Matt Pocock 的今日提示词：`/grill-me on how a /software-factory might help us`**：用他的 /grill-me 技能反复追问，配合新写的 software-factory 技能，帮你判断「软件工厂」（自动触发的 agent 流水线）对团队是否有用，并梳理需要的基础设施。这个技能把概念拆成任务、触发器、运行、执行器，以及工单系统、Git 托管、编排器、可观测平台几个槽位，建议「先慢后快」：每个触发器都是加速器，刹车是自动检查、自动审查和人工审查。原帖 1200 多收藏。https://x.com/mattpocockuk/status/2113196247964074322 ｜ https://github.com/mattpocock/skills/pull/1316
2. **编码 agent 的沙箱分三层，以及该把什么放进沙箱**：Paul Iusztin 在自己从零写的编码 agent Decode 里实现了沙箱：第一层是系统级沙箱（macOS 的 Seatbelt、Linux 的 Bubblewrap），共享宿主内核；第二层是 gVisor 这类用户态内核，拦截系统调用；第三层是 Firecracker 等 microVM，有独立内核，隔离最强。他的建议是 harness 留在本地，只把 Bash、Read、Write、Edit 这些工具放进同一个沙箱，保证它们看到同一个文件系统；Decode 用一个执行器接口同时支持本地、Docker 和 Modal 远程沙箱。https://x.com/pauliusztin_/status/2113246493763088553
3. **Peter Yang 实测 Claude Duet：最主动，但「手脚」还不全**：Duet 默认从早 9 点到晚 10 点每三小时自动 check-in，翻邮箱和日历找能代办的事，他觉得一天五次偏多；他先让 Duet 读了自己 33 封邮件、89 条 Slack 消息等写出个人写作风格指南，再让它代回邮件。短板是叫 Uber 卡在人机验证，用户看不到也碰不到它的云端浏览器，本地个人 skill 也加不进去。他把 Duet 和 Grok Bot、Muse、ChatGPT Dots 做了对比。Mai Yang 配了中英字幕和时间点摘录。https://x.com/MaiYangAI/status/2113242649457316078
4. **今天先别忙着玩新模型，检查一遍依赖**：Philipp Schmid 提醒，用 Railway、LiteLLM、PHP、GitLab、Node（brotli）的都要检查环境，「即使你觉得自己没受影响」，并附上给 agent 用的排查提示词和链接。对应今天的 LiteLLM 投毒、PHP2Shell、GitLab 高危漏洞、Railway 环境变量泄露和 Node 安全更新，可以直接把提示词交给编码 agent 跑一遍。https://x.com/_philschmid/status/2113163416638562791
