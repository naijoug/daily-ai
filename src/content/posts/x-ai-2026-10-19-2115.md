## AI 热点
1. **腾讯开源 Octop：自托管、多用户的 agent 工作台**（Gorden Sun 推荐，160 收藏）：每个用户有独立登录，可以建多个 agent，每个 agent 自带独立工作区、浏览器、终端和远程桌面，Web 控制台里能直接接管键鼠；支持多个专家 agent 由协调者调度、自然语言配 Cron 常驻任务，可以把活转给 Claude Code、Codex、Cursor、OpenCode 等，也能接微信、飞书、Telegram、Discord。官方说一条 `octop run` 就能跑起来，适合部署到自己的 VPS 或 NAS 上。[Gorden Sun](https://x.com/Gorden_Sun/status/2112066561964130734) ｜ [腾讯官方帖](https://x.com/TencentAI_News/status/2107381137740120216) ｜ [GitHub](https://github.com/TencentCloud/Octop)
2. **普林斯顿 + Google 新论文：agent 里大部分「选下一步」交给 4B 小模型**（Rohan Paul 转述）：agent harness 每一步都调大模型，但很多调用其实只是在列表里选一项（比如下一步用哪个工具）。他们让一个快速决策模型回答这些选择题，只有置信度超过阈值（用 agent 自己的运行记录拟合）时才采纳；单独答题最准的决策模型只完成 69.5% 的 agent 任务，而在 agent 实际会走到的状态（包括犯错之后）上训练的 AgentDecision-4B 完成 91.5%。在和训练数据相近的任务上，成本降 81.1%–89.0%、最快 2.5 倍，成功率差距在 3 分以内；不设阈值、把所有工具选择都交出去则掉 19 分。论文名 "JevAgentHarness"，arXiv 2610.21412。[原帖](https://x.com/rohanpaul_ai/status/2112107486098473471)
3. **swyx：「数据工程师 > AI 工程师」**（596 赞、600+ 收藏）：他说「RAG 工程师」和做「数据密集型应用」的人差别很大，现在两者的市场需求差距是他从业以来最悬殊的，并在为 Latent Space 招这类人。对正在规划方向的工程师是个信号：底层数据系统能力比会搭 RAG 更稀缺。[原帖](https://x.com/swyx/status/2112073533794971941)
4. **DHH：在中国用 Tailscale 访问 Claude Code**：有人问 DHH 来中国能不能用 Claude Code，他回复说自己所有 Claude Code 流量都走自己的 tailscale 网络（原回复 700+ 赞），歸藏转发吐槽「DHH 很懂了」。[歸藏](https://x.com/op7418/status/2112114363624800300) ｜ [DHH 原回复](https://x.com/dhh/status/2112095267873014079)

## 有趣用法和干货
1. **安全挖洞 agent 先量 token 花在哪**（Rohan Paul 转述论文）：统计 4 个 agent 的 200 次运行，60.4% 的 token 花在理解代码和推理怎么触发漏洞上；现有通用省钱技巧和普通 agent 正面对比，只有 24.4% 能在不掉成功率的前提下省钱。作者做了 AVRI，把相关代码一起返回，并保存「程序输入 → 不安全操作」之间的关联，在 20 个新任务上让 Codex 总成本降 18.0%、OpenCode 降 23.7%，成功率和召回不降。启示：给 agent 加省钱技巧之前，先看清 token 去了哪，并让它复用对代码已有的理解。[原帖](https://x.com/rohanpaul_ai/status/2112091251155825108)
2. **做 agent 记忆，要直接测「存进去的事实」**（Rohan Paul 转述 Amazon 论文）：现有记忆评测只看最终回答，把记忆、检索、回答写作混在一起，强模型能掩盖坏掉的记忆库。他们做了 FEB-30（30 段脚本化事实历史、147 份文档，每份文档后的正确记忆状态都已知），在类 Mem0/Hindsight 的系统上发现：存储事实得分和 QA 得分平均差 16.8 分，21% 的案例通过/失败判定相反，系统只有 20.1% 的时候选对了 update/reinforce 这类记忆操作，QA 完全看不出来。做法：每次更新后直接校验存储的事实，再配端到端 QA。[原帖](https://x.com/rohanpaul_ai/status/2112061760626946307)
3. **elvis 补充 Thorsten Ball 的建议：尽早学会度量和写 evals**：他同意系统思维排第一，用 agent 干活就是要按子系统去想；另外要加一条，学会衡量结果、搭 eval，「不客观度量你做的东西，就很难知道是否真的在进步」，可以用 agent 帮你起步，但一定要自己看数据和 trace。[原帖](https://x.com/omarsar0/status/2112164960574779508)
4. **ai-job-search：用 Claude Code 做的开源求职工具**（铁锤人推荐）：读取你的经历、筛选匹配岗位、按岗位要求改简历并生成求职信，还会让另一个 agent 复核导出的 PDF 能否被招聘系统（ATS）正确解析。要反复针对不同岗位改简历的可以试试，「另一个 agent 复核产出」这个模式也值得借鉴。[原帖](https://x.com/lxfater/status/2112169810050097231)
